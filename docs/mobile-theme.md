## 手机 / 平板适配

> 这一节记录的是 MDUI 时期那次手机适配的过程与量法。界面搬到 React 19 + HeroUI v3 之后，
> `.wrap` / `.dpanel` / `--fs-*` 这些类名已不在现有代码里（`web/src/styles.css` 只剩 `.scroll-thin`、
> `.num` 等少数几条）；量法与结论仍然成立，当前实现见 [frontend.md](frontend.md)，
> 抽屉的现状见下面那一条。

改法是靠量的，不是靠猜的：把首页、结果页、后台面板分别塞进 **320 / 360 / 390 / 768 / 1440**
五档 iframe（媒体查询按 iframe 自己的视口算），量完再改，改完复量。四组数：

| 量什么 | 改之前 | 改之后 |
| --- | --- | --- |
| 320px 屏上留给内容的净宽 | 249px（`.wrap` 是 `100% - 48px` 再左右各 24px 内边距，31% 的屏被边距吃掉） | 285px（360→325、390→355、768→657） |
| 小于 12px 的文字 | 91 处（11 / 11.5px 的次要信息） | 0 处 |
| 高度不足 30px 的可点元素 | 22 处（海报角上那颗「详情」只有 37×19px） | 0 处（详情按钮 44×32，片名 44，后台表格里的链接 17→31） |
| 文档横向溢出 | 首页 377>360 能横着拖；后台 360 溢 100px、390 溢 70px | 全部 0 |

具体做的几件事：

- **把宽度还给内容。** ≤640px 时 `.wrap` 改成整宽只留 10px 内边距；四个标签不再各自换成 98px
  高的砖，而是一行横滑（`.tabs` 内部 `overflow-x:auto`，滚动条藏掉）。后台那些表也是同一类问题：
  表在滚动框里还被 `width:100%` 挤着，而中文能按字折行，十二列的明细在 320 上一行撑到
  151px 高、字全竖着排。改成 `.fold table { width: max-content; min-width: 100% }` 之后
  行回到 31px（合流以后点开行与搜索行同一张表，320 上实测 15 行全是 31px），多余的去横向滚 ——
  横向滚动是看得见的，竖着排的字是读不动的。
- **小字号与输入框字号都走 token**（`--fs-min` / `--fs-sm` / `--fs-input`），窄屏只抬 token。
  `--fs-input` 是为了 iOS：聚焦字号小于 16px 的输入框时 Safari 会把整页放大且缩不回去，
  后台那些 12.5px 的筛选框必须抬到 16px。
- **触摸目标按用途给，不是一刀切 44px。** 访客用的猜你想搜片名给到 44；后台表格里那些筛选链接
  和结果没回来那几秒显示的那份给爬虫的列表（`.ssrlist`）都用"内边距 + 等量负外边距"撑开
  （表格链接 17→31，列表链接 17→34）—— 实测行高一个像素没变（31/31/30/31/31，整表 122px，
  加这条规则前后一样），只是按得准了。
- **手机上的详情是居中弹框**（2026-10 起，不再是右侧/底部的抽屉）：背后一层透明遮罩
  （不暗、不糊，页面原样露着），关掉即恢复，内容超高在框内滚。展开是**从点击处环形
  揭示**的 View Transition（弹框原位不动，一个以点击点为圆心的圆把它荡开；不支持或
  `prefers-reduced-motion` 时退回就地淡入），见 [detail.md](detail.md)。
  弹框里的观看地址同样一行一条线路、点了才铺集数（360 上实测：展开一条 36 集的线路，
  集数格子 67×34，没有一个是够不着的触摸目标，文档横向溢出仍然是 0）。
- **登录那张卡片在手机上也改成整宽**。`口令 + 进入` 原本是横排，320 上卡片内宽只剩 253px，
  flex 把按钮压成 42×51（"进入"两个字换了行）；≤560 改成各占一整行，输入框吃满（235×43）、
  按钮 235×40。561 以上仍是横排 —— 360 上卡片内宽 293，本来就放得下，没必要竖着。

踩过的四个坑，都写进测试了（`tests/test_agent_theme.py` 第 11 节，28 条）：

1. 覆盖规则必须留在**文件最后**。同优先度的规则按先后取胜，第一次把窄屏那段写在中间，
   字号看着改了、量出来还是 11.5px。
2. **媒体查询不加特异性**。`input { font-size:16px }` 是 (0,0,1)，压不住 `.admfield input`
   的 (0,1,1) —— 所以真正起作用的是 token，兜底那条只是给没走 token 的控件用的。
3. **flex / grid 项默认 `min-width:auto`**，不肯缩到比内容更窄：四个不换行的标签能把整个文档
   顶宽（不是标签条自己横滚），后台收成单列后一长串 `python -m ...` 命令也能顶宽。
   解法都是 `min-width: 0`，让该横滚的那层（`.tabs`、`.fold`）自己去滚。
4. 断长 token 要用 **`overflow-wrap: anywhere`**，不是 `break-word`：只有 `anywhere` 参与
   min-content 计算，`break-word` 写得再对也照样把列顶宽。

复量的办法没留在仓库里（探针页是会被人访问到的，量完就删了）：在站点任意页的控制台里
`document.createElement('iframe')` 设成 320/360/390/768/1440 宽指向 `/`、`/s/庆余年`、`/admin`，
媒体查询按 iframe 自己的视口算，量 `documentElement.scrollWidth - clientWidth`、每个 `a/button/input`
的 `getBoundingClientRect().height`、以及计算样式里小于 12px 的字号。后台面板要连着数据一起量，
就先在服务端把 `/admin` 渲染成快照再剥掉 `<script>`（折叠高度是 JS 量的，量布局不需要它）。
注意别把窗口缩到 900 以下来"假装手机"——那连的是窄桌面，`hover: none` 那些行为不一样。



### 主题（亮 / 暗 / 跟随系统）

标题旁那颗按钮点一下在 **跟随系统 → 亮色 → 暗色** 之间循环，默认"跟随系统"，
选"跟随系统"时还监听系统配色变化，切了立刻跟着变。前台记在 `localStorage['heroui-theme']`
（HeroUI 的 `useTheme`），后台那份 React 用的也是同一个键，只有"禁用 JS 提交登录"那张兜底页
还靠 `static/theme.js` 写同一对属性 —— 所以切一次亮/暗，前后台一起翻面；边界见
[frontend.md](frontend.md)。

实现上有三点值得记：

- 前台**没有自己的调色板**：颜色一律写 `bg-background` / `text-muted` / `ring-border`
  这些 HeroUI 令牌名，暗色时 `<html class="dark">` / `data-theme="dark"` 把整组变量覆盖一遍，
  并声明 `color-scheme: dark`（表单控件、滚动条、原生日期选择器才会跟着变）。
  唯一的例外是主色：`styles.css` 里把 `--accent` 压深一档。加新样式时只要用令牌名写颜色，
  两套主题就自动都成立 —— 手写十六进制的那一处，永远只在一套主题下是对的。
- Tailwind v4 的 `dark:` 变体默认问的是 `prefers-color-scheme`，而令牌问的是 `<html>` 上的属性；
  "系统是暗色但手动强制亮色"时两者会分家，所以 `@custom-variant dark (&:where(.dark, .dark *))`
  把变体也改成问同一个属性。
- 主题必须在样式表加载前就定下来，否则暗色用户每次刷新都会闪一下白。所以 `shell.html` 里
  读值是**内联**在 `<head>` 的一段脚本，不能改成 `defer` 或外链（要多一次网络往返）。
  副作用是完全禁用 JS 时拿不到系统偏好、固定在亮色 —— 那条路上本来就只剩 `#nojs` 那份
  服务端渲染的列表，是笔划算的取舍。
- 切换是**渐变**的，但过渡只在切换那 380ms 里临时挂一个 `.theme-anim` 类，之后立刻摘掉。
  写成常驻的 `* { transition: … }` 会把 hover/focus 原有的短过渡全拖成 300ms，
  长列表滚动还会掉帧。`prefers-reduced-motion: reduce` 时完全不渐变、海报淡入关掉，
  「猜你想搜」的 ‹ › 也改成瞬时跳（`scrollBy` 的 `behavior: "auto"`）。首屏不走这条路径
  （由预置脚本直接定色），所以打开时不会先闪一遍。

### 配色体检

`tests/test_agent_theme.py` 会把页面里成对出现的颜色算 WCAG 对比度（文字/底色九对上下，
亮暗各一遍），低于 4.5 就报错。它查出来的第一批问题是这类：主按钮蓝底上写了红字
（一次批量替换的失误）、次级文字 2.98 让 11–12px 的小字基本看不清、成功/警告/失败三档
全在 3.3–4.2 之间。修完之后是 5.0 / 4.8 / 5.4 / 5.3 / 4.8。

按钮、输入框一律药丸（`rounded-full`），卡片才用大方角；次级动作一律淡底 + 悬停转品牌色，
不用红色暗示"危险"（清空筛选不是删库）；所有数字（命中数、耗时、页码、条数）走 `.num`
等宽 + `tabular-nums`，这样右对齐时不会抖成一片。

## 阅读宽度与栅格：前后台同一档

前台与后台的上限都是 `max-w-[1680px]`（前台的页头 / 主体 / 页脚各一处，后台页头一处），
边距随屏给（`px-4 sm:px-6`），不再各用一档：

| 页面 | 上限 | 为什么 |
| --- | --- | --- |
| 前台 | 1680px | 与后台对齐；结果区是卡片墙不是长文，宽一点多放一列更有用 |
| 后台 | 1680px | 明细表、归属地表本来就要横向铺得开，那是数据不是正文 |

搜索那一屏在 ≥1280px（`xl`）时是两栏：`xl:grid-cols-[minmax(0,1fr)_320px]`，
左边结果、右边资料栏（接口状态 + 检索摘要），右栏 `xl:sticky xl:top-20` 粘性跟随。
窄屏没有右栏：`<aside>` 是 `max-xl:contents`，里面两块各自成为栅格项，跟着结果依次排在
后面 —— 接口状态在前、《X》的检索结果在后（`order-first` 那个写法会把接口状态顶到结果
上面，手机上等于把结果推出半屏，别写回去）。两块都跟着屏宽走：宽屏默认展开，窄屏默认折叠。

「《X》的检索结果」快照在窄屏折成一行；展开后固定 6 行、框内滚动。高度取第 7 条 `li` 的
`offsetTop`，且第一次必须同步量（rAF 在后台标签里不回调，异步量等于没设限高）。
这一块跟着当前搜索词走：SPA 换词时 `/api/search` 第一页会把新词的快照一并带回来，
所以不用刷新整页也能在右栏底部看到「《新词》的检索结果」。

落地页（没关键词）不启用两栏：那时右边没有内容，会空出一整栏，所以「猜你想搜」继续横铺整行。

接口状态这块以前横排在结果上方，15 个源挤成三行药丸，谁快谁慢扫不出来。现在一行一个源
（`grid-cols-[7px_minmax(0,1fr)_auto_46px]`）：状态点、名字、命中数、耗时，后两段右对齐走等宽，
顶上还有一句"15/15 可用"；超过 3 秒的源耗时转警告色，一眼能看出是谁在拖。
