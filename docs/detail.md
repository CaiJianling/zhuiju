# 详情面板与观看点击

点击处环形揭示详情弹框、返回时圆收回去、线路折叠、点开行为怎么落库、后台为什么默认只看最近一周。

← 返回 [README](../README.md)：这台机器怎么跑起来、口令在哪、能做什么不能做什么，都在那一页。

## 从点击处环形揭示的详情弹框，返回时缩回原处

每张海报（结果卡片与猜你想搜都有）本身就是一颗铺满封面的按钮，右下角还常驻一颗小的**详情**药丸；
两者都调用 `openDetail(spec, coverEl)`，把"用户点的是哪个封面矩形"一起带过去。详情是**居中弹框**
（HeroUI Modal，`size="md"`）：**导演 / 主演 / 年份 / 地区 / 类型 / 更新状态 +
简介 + 观看地址**。宽高**只跟窗口走**（宽 `min(560px, 100vw − 2rem)`、高 `min(760px, 84dvh)`），
骨架屏、详情、展开线路三种状态一样大 —— 内容超高在框内滚，弹框本身不长不缩。
下面一排来源按钮照旧：多个源时写「换源看」，只有一个源时写「来源」并把那颗点亮 ——
这一行说的是"这条详情是哪个源给的"，不能因为只有一个源就整排消失。

**展开是从点击处荡开的一个环形揭示**（安卓 material ripple 那种）。点下去时算出被点
封面矩形的中心，进 `document.startViewTransition` 的回调 —— 回调里 `flushSync` 把 spec
**同步**提交（新状态的快照在回调返回后下一帧就拍，React 异步提交赶不上那一拍），随后
现量刚挂上的弹框矩形，把点击点换算成弹框本地坐标写进 root 的变量：

- `--vt-lx/--vt-ly`：点击点在弹框盒子里的坐标；`--vt-r`：盖住弹框最远一角的半径
  —— 弹框本体（`.detail-sheet`）的 `sheet-open` 用它做 `clip-path: circle()`。

于是弹框**在原位一动不动**（背后那层遮罩走的是 `variant="transparent"`，不暗不糊，
页面原样露着），一个以点击点为圆心的圆把弹框"荡"开：圆缘扫到哪儿哪儿显现，扫过
弹框轮廓的那一拍，`sheet-ripple` 那圈 box-shadow 像水纹一样荡出去再散掉。
**海报自己不参与过渡**（早先那版"海报飞进弹框"的 morph 已删：弹框里那张就是同一张图，
让它再飞一遍是重复叙事）。弹框层盖在整屏快照之上（`::view-transition-group` 的 z-index）。

**返回时是同一个圆反向收拢，不是淡出。** 点「返回」（Esc、×、点遮罩同路）时弹框还挂着，
先把圆心与半径量好写进变量，再把浮层（`.detail-backdrop`）`display:none` 整块从绘制里拿掉、
`flushSync` 提交卸载 —— 浮层必须先拿掉：RAC 关闭时会把退出中的浮层多挂一小段，新状态里留一个
`detail-sheet` 的影子，收拢动画就对不上位置。干净的新状态里 `detail-sheet` 只存在于旧快照，
`sheet-close` 便把弹框沿同一个圆缩回点击处。

不支持 View Transitions 的浏览器（老 Firefox）与 `prefers-reduced-motion: reduce` 不参与这场揭示，
弹框就地淡入。这条判据集中在 `vtOn` 一处，不散在各点击点。弹框左上角是「返回」，右上角是 ×，
Esc 与点遮罩也能关；关闭后焦点还给开它的那颗控件（`vtBack` 记的是 `document.activeElement`）——
键盘与读屏的人回来时还停在原处。

几个刻意的取舍：

- **观看地址放在弹框里，但一行一条线路，集数点了才铺。** 一部 36 集的剧一次渲染上百个 `<a>`
  会把一屏塞成一片按钮墙（弹框尺寸按窗口固定，多出来的只能在框里滚，第一次进来就得先滚过一片
  没人点的集数）；所以每条线路只写线路名与条数，第一次展开才铺那一串集数
  （`aria-expanded` 跟着变，每线路截 120 集，多出来的提示去看完整页）。
- **点了哪条观看地址会记进库。** 面板里点的记 `panel`，卡片里展开来源名点的记 `card`，
  见下面「详情与观看点击」一节。
- **绝不预取。** 详情数据只在点了按钮之后才要：弹框先用 `DetailSpec` 已有的信息（片名、年份、地区、
  主演、海报、覆盖源数）把内容铺出来，其余等一次 `ac=detail` 回来填，中间是骨架屏。
  `tests/test_detail.py` 用"海报组件里不许出现 `detailURL` / `openDetail` 之外的取数"钉住这一点。
- **不再劫持右键。** 海报右键就是浏览器原生的保存图片 / 检查，页面上任何地方都不挂 `contextmenu`。
- **卡片不是整块一个链接。** 按钮不能嵌在 `<a>` 里，所以封面负责详情、片名负责进页面。
- **两条来路，代价差一个量级。** 搜索结果每个来源都带影片 ID，一次 `ac=detail` 就够（实测 1–4s）；
  猜你想搜历史上只有片名，得先并发检索一轮才知道 ID —— 所以 `hot.py` 现在把 `(源, 影片 ID)`
  一起写进缓存行（`pack_row` 的 `src`/`vid`）。旧缓存里没这对值时前端自动退回按片名查，
  并在面板里写明"要慢几秒"。服务端对按片名的结果缓存 15 分钟，且**只缓存成功的**
  （失败多半是某个源此刻不通，把失败钉 15 分钟反而更糟）。
- **两条来路都有「换源看」。** 结果卡片每个来源都带影片 ID；猜你想搜那一行也带着
  `(源, ID)` 列表（见 [docs/hot.md](hot.md) 的「猜你想搜」一节），`DetailSpec.sources`
  一起交给弹框，面板才换得动。
- **重复开关不重复请求。** 弹框按 `源:ID:片名` 在内存里缓存结果（`Map`，刷新即失效），
  连点同一部片直接用缓存并写明"这一条本页已经查过"；切源或切片时用自增 token 丢弃在途结果，
  不会把 A 的详情填进 B。失败留一个「重试」并把这笔缓存清掉。
- **弹框是模态的。** 背后有一层透明的交互层（不暗、不糊，但挡着后面的操作与滚动），
  开的时候不再和后面的搜索/翻页打架；Esc、×、返回、点遮罩四种都能关。

`/api/detail` 的入参因此是：`?src=<源>&vid=<影片 ID>`（优先）或 `?kw=<片名>`（兜底）；
两个都给不上就 400，源停用则 404 并说明原因，不会偷偷去按片名查。返回里连着 `lines`
（线路名 + 逐集地址）一起给，折不折叠是前端的事。


## 详情与观看点击：搜完之后有没有人真去看

只记查询数分不出"搜一眼就走"和"真找到能看的"。所以两类点击都记：`POST /api/click`，
`kind=detail` 是点了海报上的**详情**按钮，`kind=play` 是点开了某条**观看地址**。
前端用 `navigator.sendBeacon` 发（没有就退 `fetch + keepalive`），**不 `preventDefault`** ——
点了就是要打开那个播放页，埋点不能把它挡住。

写进 `clicks` 表（和 `queries` 同一个 `stats.db`，同一条 `KEEP_DAYS` 界线清理）：
时间、`kind`、IP、关键词、片名、源、线路名、集名、目标 URL 与它的**域名**、`place`
（`hot` = 猜你想搜的海报、`card` = 结果卡片的海报或展开的线路、`panel` = 详情面板里的线路）、
UA 与认出来的浏览器/爬虫标记。域名单独存一列，因为"都点了哪些站"按域名聚合才有意义，整条 URL 太碎。
`detail` 那一笔本来就没有地址，所以 scheme 校验只作用于 `play`。换成另一个源等于又看了一次
详情，所以也记一条 `detail`；点当前那个源不记（它本来就不重开）。

后台不另开一张点击表，**点开行为就是明细里的行**，与搜索记录合在同一张表按时间倒序排：
`全部 / 只看搜索 / 只看点开` 三个胶囊切范围（`scope=all|query|click`），切换回第 1 页 ——
两边条数不一样，停在旧页码等于给人看空页。第一排的统计格 `详情 N / 观看 M` 直接跳到"只看点开"。

为什么不挂在搜索行下面展开：点开行为的关键词是前端带的片名，从「猜你想搜」海报点进来的人
**根本没搜过它**。实测库里 15 条点击按 `(ip, 关键词)` 能对上搜索记录的有 **0 条** ——
挂在搜索行底下就等于一条都看不见。合流以后"搜了 → 点详情 → 点播放"从上往下读就是过程。

- 一行里的列按两张表各自的含义复用：「来源页」对搜索是 Referer、对点开是 `place`
  （海报详情 / 卡片线路 / 猜你想搜），「入口」对搜索是 `via`、对点开是 `kind`（详情 / 观看地址），
  「关键词」那一格点开行写片名 + 源 + 线路 + 第几集 + 目标域名。
  搜索才有的数字（结果 / 原始命中 / 可用源 / 耗时）在点开行是 **NULL，渲染成破折号** ——
  写 0 会被读成"搜了没结果"。
- 筛选与聚合仍是 `click_stats()` 一次拿全（总量、独立 IP、按域名、按 `place`、按 `kind`），
  明细一次 `UNION ALL` 拿列表，都不按行发查询。
- 按「入口 / 来源」筛的是搜索那一侧的列，点开行没有这两列会被一起排除掉 ——
  这件事写在明细标题上，不静默少一半。

必须守住的边界（都有测试）：

- **`play` 只收 `http(s)`。** 这一列的值由客户端写，进后台是要当链接点的，`javascript:` 混进来
  就是自己给自己留 XSS；不是 http(s) 的一律不进库。
- **字段全部截断**（URL 300、关键词 60、片名 80、线路/集名 40、源与 ID 32），`place`/`kind`
  不在枚举里分别退回 `card`/`play`。
- **按 IP 限流**（默认一分钟 120 条，`CLICK_MAX` / `CLICK_WINDOW` 在 `app.py`），正文上限 16KB。
  这是个公开接口，不设上限等于邀请人拿脚本把统计库灌满；超了照样回 204 —— 回 4xx 只会让
  前端以为没发出去而重试。
- 已经建过 `clicks` 的老库没有 `kind`，也没有归属地与浏览器那六列：`ensure_schema()` 一次补完
  （`CLICK_COLUMNS`），再 `normalize_clicks()` 按留存的 `ip` / `ua` 回填一次，新老行才是同一套口径。
  老行本来就没存 UA，所以认不出来就按统一写法存成 `未知`（见 [docs/admin.md](admin.md) 的「认不出来」那一节），不留 NULL；
  归属地库还没下载时**先不补** —— 补了就分不清"没解析过"和"解析成内网"了。
  读的地方再 `COALESCE` 兜一层，别让一个后补的列把聚合劈成两半。
- 这两张表的过滤条件共用一份 `_where()`（`clicks` 也支持 ip / 关键词 / 日期 / 浏览器 / 系统 /
  设备 / 归属地）：分开写两份迟早会漂，合成一张列表以后"按浏览器筛"必须两张表都筛得动。

播放页是第三方的，点开就跳过去了，本站只知道"点开了"，不知道最后看不看得成。


## 后台默认只看最近一周

日期什么都不选时 `/admin` 取**最近 7 天**（`ZHUIJU_ADMIN_DAYS` 可改，含今天），日期框里回填的就是
实际用的这个区间，页面上也写明"最近 7 天（起 ～ 止）"。不这么干用得越久这页越长，而"今天有没有
人用"恰恰是最想知道的。`queries` 与 `clicks` 吃同一把尺子（同一份 `_where()`、同一批表单值），
否则明细筛了最近一周、上面那几个统计格与下面的汇总却数的是全部历史。

出口是 `?day=all`：页面上那条「看全部历史」带上它，**翻页链接、筛选表单和跳转表单的隐藏域也跟着带**
—— 否则点一次"下一页"或筛个 IP 就会被默认值悄悄送回一周。反过来，URL 里显式给了 `day_from` /
`day_to` 时，默认值绝不顶掉它。

顺带修了一个真会 500 的地方：归属地没回填成的老行 `iso` 是 NULL，而模板写的是
`r.iso | default('') | length` —— Jinja 的 `default` 只管"键不存在"，不管值是 `None`，
于是那一页直接报 `object of type 'NoneType' has no len()`。改成 `(r.iso or '') | length`。


## 状态用条件渲染，不用 hidden

老模板时代踩过一个反复复发的坑：浏览器自带的 `[hidden] { display: none }` 只是 **UA 样式**，
作者样式表里任何一条 `display:` 都能压过它。`.pager { display: flex }`、`.statline` 这类规则
让"明明该藏起来的上一页/下一页"继续摆在页面上，而 JS 侧一切正常 —— `el.hidden` 读出来就是 `true`。
**这个 bug 从属性里量不出来**，只能量它到底显不显示（`getComputedStyle(el).display`、`offsetHeight`）。

现在的界面对"有没有"这回事一律走 React 条件渲染：没有词就不渲染结果叠，没有更多页就不渲染哨兵
之外的邀请，换词后服务端摘要的判据不成立就整块不渲染。不再有"元素还在、只是加了 hidden"这种
两套真相；也不要在 React 里退回 `hidden` 属性做显隐 —— 这层坑没必要重新踩一遍。

顺带一条同类发现：站点在两轮修改之间**进程死掉过**（`logs/server.out` 停在 10:40:55，5000 端口没人监听），
`restart.py` 是用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 起的手工分离进程，但它仍然会随
上一轮 CLI 进程树结束而没了。所以"改完没生效"先要确认的其实是**站点还在不在**：
`python tools/restart.py` 会先杀干净监听者再起来，并用"只有当前这版代码才有的特征路由"判就绪。
