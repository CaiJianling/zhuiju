# 追剧资源搜索（本地站点）

一个跑在自己电脑上的 Flask 网站：一个搜索框，输入电影 / 电视剧 / 动漫名称，同时查多个公开影视采集接口，把同名结果合并成一部片，并附上网盘、磁力、资源站的直达入口。

参考了 [awesome-zhuiju-free](https://github.com/laoma528/awesome-zhuiju-free) 的资源清单（`精选资源` 章节），检索接口取自其 TVBox 配置项并逐个实测，目录数据取自其 `resources/resources.json` 的事实字段（名称 / 地址 / 分类 / 标签 / 评分 / 可用状态）。

## 快速开始

双击 `启动.bat` 即可（首次会自动建虚拟环境并用清华源装依赖，之后直接起服务、自动开浏览器）。

手动方式：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv\Scripts\python.exe run.py
```

打开 <http://127.0.0.1:5000/> 。想换端口：`set ZHUIJU_PORT=8000 && .venv\Scripts\python.exe run.py`。

后台统计在 <http://127.0.0.1:5000/admin>。**第一次进去会直接领你把口令改成自己定的**
（那时用的还是首次启动随机生成、只在控制台打印过一次的那个），保存即写回
`zhuiju/data/admin.json` 并生效，不用重启。详见"后台统计"一节。

## 四个标签页

| 标签页 | 内容 |
| --- | --- |
| 影视资源 | 10 个采集接口并发查询，同一部片按归一化片名合并，显示类型 / 年份 / 地区 / 更新状态 / 海报；点来源名展开该源的播放线路（多线路、逐集链接）；海报右下角的「详情」按钮给出影片信息与观看地址，线路一行一条、集数点了才铺 |
| 网盘查询 | **点进标签页才发请求**：服务端并发抓取网盘 / 磁力站的搜索结果页并解析出条目（标题 + 该站详情页链接）；解析不出来的站逐条写明原因并给"打开该站搜索页"入口。**没输关键词时不再是一句"先搜索"**：直接把这一页会用到的 20 个站列出来（本站能直接搜出结果的 / 只能打开该站自己搜的），这份清单只读目录与模板，一个请求都不发 |
| 网盘 · 磁力直达 | 76 个网盘 / 磁力 / 在线站 / 字幕站的入口，**不搜也有内容**（进页面即加载各站首页）；搜索后其中 18 个会直接带着关键词打开其站内搜索页 |
| 资源站目录 | 按**分类浏览**收录站点（不是拿影片名去匹配站名），带推荐指数和上游每日检测结果（🟢 可访问 / 🟡 受限 / 🔴 无法访问）；搜过片名之后每行多一个「搜此片」直达链接 |

「网盘查询」的实际覆盖要如实说明：目录里的网盘 / 磁力站大多把搜索框做成 POST 表单或 JS 提交，服务端抓不到结果（实测每种 GET/POST 变体返回的都是同一个 JS 空壳，页面大小和首页一致），只能标注原因 + 打开该站；能解析出条目靠的是 `data/templates.json` 里**已验证的 GET 搜索模板**，判据只有一个（`verify_get_templates.py` 双关键词差分验过），模板表每次更新都会重写，所以这个数会随时间掉。当前状态：**网盘 / 磁力这两类 20 个站里 0 个有可用模板**（表里剩的两条是字幕站，不在这个标签页范围内），所以这一页现在把所有站都归到"只能自己打开"。历史上抓到过：庆余年 20 站中 3 站出结果、共 16 条。只收与搜索页同域的链接——结果页上的跨域链接基本都是广告。

也正因为如此，**没输关键词时这个标签页不该空着**：`/api/cloud` 不带 `kw` 返回 `mode:"sites"` 的站点清单（`cloudsearch.site_rows()`，纯读目录 + 模板，一个请求都不发，也不写统计），页面把每个站的推荐指数、状态、能不能直接搜、首页链接摊开，有模板的还多显示一行搜索页模板（留着 `{kw}` 占位，而不是把空串填进去伪装成可用链接）。"能不能直接搜"用的判据与 `query_site()` 完全一致，清单和真搜起来不会两张皮。

**标签栏一直显示着，不跟着"有没有搜索"开关**：`#statline` 里那四个标签是进这几个面板的唯一入口，
而「网盘查询」的站点清单和「资源站目录」都不需要关键词。以前 JS 里确实按 `statline.hidden` 开关它，
但那行从来没生效过 —— CSS 的 `.statline { display: flex }` 把浏览器自带的 `[hidden]` 压掉了（见下面
「hidden 必须真能藏住东西」），所以它一直是露出来的，功能也就一直能用。现在把这个事实写进设计里：
`hidden` 属性从模板和 JS 里都去掉了，随搜索变的只有它右边那行 `#meta`（"命中 N 部…"）。

结果按匹配强度分层排序：完全同名 > 同系列版本（续集 / 特别版）> 近似名称 > 模糊匹配，同层再按"有几个源收录"排，所以《灌篮高手》不会被《灌篮高手的契约》这类蹭名短剧压下去。归一化后与关键词零重叠的结果（各源自身模糊匹配吐出来的噪声）会直接丢掉并在页面顶上标出条数——搜英文片名时尤其明显，`Oppenheimer` 从 13 条噪声收窄到 2 条相关。关键词至少 2 个字符，单字符会触发一轮无意义的并发抓取，直接拒掉。

## 猜你想搜（空关键词时）

搜索框为空时，下方展示**电影**和**电视剧**两个区域，按**更新时间从新到旧**排列。**每区固定一行，用「‹ 上一页 / 下一页 ›」整行切换**，不是横向拖动条——网格是 `repeat(var(--hot-cols), 1fr)` 且不带 `overflow-x`，所以 `scrollWidth == clientWidth`，永远不会出现滚动条。

每页张数不是写死的：CSS 按断点决定列数（≥1180px 6 列 → 1180 5 列 → 960 4 列 → 720 3 列 → 520 2 列），JS 从 `getComputedStyle(grid).gridTemplateColumns` 把实际列数读回来当每页张数，两边共用同一个来源；窗口缩放时防抖重铺当前页。组标题右侧显示「第 m / n 页」，到头自动禁用。

服务端仍然渲染 12 张（`_first_row(per=12)`）给爬虫和不执行 JS 的访问者，JS 起来后按列数重铺第 0 页——这 12 条已经在 `boot-data` 里，所以首屏不额外发请求。

翻页走 `/api/hot?kind=movie&offset=<page*cols>&limit=<cols>`，`offset` 越界返回空列表不报错。曾经的两个坑都由 `tests/test_seo_hot.py` 第 7、8 节锁死：① 按钮禁用条件写成 `rows|length <= 12`，而 `rows` 已被截成一行，导致按钮永远点不动；② 用 `flex + overflow-x` 做成了横向拖动条而不是翻页。

**页数会变，这不是 bug，但停在空页上是。** 页码 = `ceil(总数 / 列数)`，而总数每次翻页都从接口重新取 —— 这份缓存每 6 小时后台重建一次，重建后的条目数本来就可能不一样（实测过电影 36 → 25）。所以"刚打开时 6 页、翻两页变 4 页"是列表真变短了，不是算错。真正的问题是人在第 6 页、新列表只有 4 页时再翻会落到 `offset` 越界的那一页：一行海报都没有，页码还写着"5 / 4"。现在 `showHotPage()` 拿回空列表且发现页码已超出时，会**夹到最后一页重取一次**（`st.page` 只会变小，不会来回弹），同时把变化写在组标题上：「列表刚更新过：36 → 25 条」。提示那条不用 `nowrap`，窄屏上不能让它把标题行顶出容器。

范围是**最近一年**（`hot.WINDOW_DAYS = 365`，以前是 183 天半年），按 `vod_time` / `vod_year` 判定；
更新时间读不出来的行退到"年份落在窗口那一年"（`_recent` 的第二判用 `since.year` 而不是写死今年 ——
半年窗口下两者等价，一年窗口下写死今年就会把整个去年的东西全否掉）。
**两类都不截条数**：池子里有多少就存多少，页面按页取。以前 `build(limit_each=60)` 每类砍到 60，
实测半年窗口下电视剧池有 287 条、被砍掉 227 条，而"多几页"本来就是 `page(kind, offset, limit)`
一次只给一行宽的事，缓存里没有预先裁的理由。点卡片会跳到该片名自己的 `/s/` 地址。

标题那一行写的是**成品数**，不是候选池大小：「最近一年 · 截至 X 起算 · 候选 334 条 → 电影 38 / 电视剧 287
（认不出类别丢掉 9 条）」。以前只写「共 346 条候选」，人自然要问"怎么翻页只有 40 + 60"——
346 是**归类之前**的池子数，两类各剩多少才是页面上真能翻到的，`dropped_kind`（实测是足球/篮球这类
体育节目，本来就不该出现在影视推荐里）也写出来，不悄悄少一批。`window_days` 一起进了缓存，
标签上的"最近一年 / 半年"跟着它走：缓存可能是旧窗口建的，标签不能提前说新话。

**翻页是两行互相推开，不是新行自己挪进来。** `showHotPage()` 在替换内容前记住旧页码，
`moving = st.page - prev` 决定方向：下一页 → 旧行向左退场、新行从右边顶进来；上一页反过来。
两边位移量都是**一整行宽（100%）**，所以全程两行正好挨着，看上去是一条连续的海报带在横移
（`.32s ease-out`，挂在整行容器上而不是每张卡上：一次合成，九张卡不会各自错开拍成洗牌）。

前两版分别被说成"闪"和"假"，根因是两个：① 第一版是"滑进 + 从透明淡上来"，换内容那一瞬间旧行已经没了、
新行还在 `opacity: 0`，整行是**全空**的 —— 那是闪；② 第二版把 opacity 去掉、只让新行位移 24px，
可旧行是"啪"地消失的，新行再凭空插进来，没有"上一行去了哪儿"的连续性 —— 那是假。
现在换内容时先把旧行那批节点搬进一个绝对定位、盖在 grid 原位置上的 `.ghost`，新行留在正常流里占住盒子高度
（进场过程中区块高度不会跳），两边各跑一条关键帧，结束后把 `.ghost` 摘掉。三个细节：方向要在改 `st.page`
**之前**取（否则永远算出 0）；`void ghost.offsetWidth` 强制重排一次，同名 class 第二次才播得动；
进场那一行必须裁在这一组里 —— `.hotgroup { position: relative; overflow-x: clip }`，用 `clip` 不用 `hidden`
（`hidden` 会把纵向也强行变成 `auto`，卡片聚焦框和下沿会被横着那条裁一刀）。
收尾走三路并且只认第一次（两边的 `animationend`、Web Animations 的 `onfinish`、480ms 定时器兜底，
`done()` 里一个 `gone` 标记）：`animationend` 不保证来（元素被隐藏、合成器不推帧、系统要求减少动效），
只靠它 `.ghost` 会一直盖在新行上面；连点两次时新推入先收尾上一次，不会叠两层 ghost。
实测（1500 宽、9 列）：下一页那一瞬间旧行 `left = -1285`、新行 `left = 67`、行宽 `1351` ——
两行间距正好等于一行宽，退场那行完全裁在组内；上一页是镜像（旧行 `+1351`）；动效结束后 `.ghost` 数为 0；
`documentElement.scrollWidth - innerWidth` 全程为负（没有横向溢出）。

**翻回来的那一页用原来那批 DOM 节点，不重建。** `hotCache[kind] = {cols, map: {页码: [卡片元素]}}`，
命中就 `grid.replaceChildren(...seen)` 直接搬回去 —— 判在取数**之前**，所以翻回来的页连
`/api/hot` 都不发。为什么要留节点而不是重画：新建 `<img>` 时哪怕浏览器不再走网络，也要重新解码一次，
`decoding="async"` 就晚一帧，整行海报再各自淡一次 —— 观感上等于"翻页把海报重新加载了一遍"。
键里带列数，窗口一变旧节点自然作废（一页装哪几条也跟着变了）。代价是缓存 6 小时重建后，
**已经看过的那一页仍显示当时看到的那一批**，这是有意的：翻回来的页不许变，没看过的页照常取新的。
实测（1180 宽）：初始 10 个 `/img` 请求，往后翻两页、再翻回首页，`/img` 计数始终 10，
`/api/hot` 只多了翻页那 2 次；翻回来的 `grid.children[0]` 与离开前是**同一个元素对象**。
列数从 5 变 3 触发的重铺里，五张海报全是 `loaded noanim`、`transition: none`、`opacity: 1`，一帧没淡。

**空关键词提交 = 回首页。** 输入框没有 `required`，清空再回车是真会走到 `run('')` 的。以前那条路只把
猜你想搜显出来、聚焦输入框，结果面板、统计条和「上一页 / 下一页」全都还挂在页面上——框里明明没词，
下一页还能点，点了又用 `state.kw`（还是上一个词）去发翻页请求。现在 `run('')` 直接调用与「首页」那颗
按钮同一个 `goHome()`：清结果、藏 pager 与统计条、显出猜你想搜；在 `/s/<词>` 落地页上则真的跳回 `/`，
否则 URL 停在一个已经没有内容的关键词页上（等于重复内容）。

**`#pager` 只在真有一次搜索的时候出现。** 上面那种"残留"其实还有两个入口，都堵上了：① 点了搜索之后结果区
先换成骨架屏，上一个词留下的翻页条同时收掉（它已经不属于屏幕上任何东西），数据回来再由 `renderPager()`
决定挂不挂；② **搜索失败以前根本不会调 `renderPager()`** —— 于是上一个词的「上一页 / 下一页」一直挂在
"检索接口无响应"那张空卡片上面，下一页还亮着，点下去用的是旧词。现在两条失败出口（接口全灭、抛异常）
都走 `pagerOnFail(page)`：第 1 页失败整条收掉，深层页失败留着「上一页」这条退路，但「下一页」按住
（还有没有得翻都不知道）。

不过要说根因：上面这三处 `hidden = true` 从来就没写错，错的是它**在页面上不生效** —— 见后面
「hidden 必须真能藏住东西」那一节，`.pager { display: flex }` 把浏览器自带的 `[hidden]` 压掉了。

**海报只有第一次真去取的时候才淡。** 海报要经 `/img` 现取现回传，比卡片本身晚半拍到，直接显示就是一张张蹦出来（整页像在闪）。
现在 `html.hasjs .cover img / .hcover img / .dpcover img` 先透明，`revealIn()` 决定怎么现身：这张图**已经见过**
（地址在 `shownPics` 里，最多记 3000 条）或浏览器已经解码好（`complete && naturalWidth`）就加
`.loaded .noanim` —— `noanim` 把过渡关掉，直接显示；只有真·第一次要等网络的那张才等 `load` 淡一次
并把地址记下来。两个坑都在实现里：① **命中缓存的图不发 `load` 事件**——`src` 一赋值就已经 `complete`，
所以原来写在 `<img onload=...>` 上的做法对这批图永远不触发，只能当场判 `complete && naturalWidth`；
② 这个淡入**必须挂在 `html.hasjs` 下**，标记由 `_theme.html` 那段内联脚本在样式表之前打上，
否则爬虫和禁用 JS 的浏览器拿不到 `.loaded`，看到的就是整片空的 🎬 占位。
图挂了走 `onerror="this.remove()"`，图没了占位自然露出来；再加一道 8 秒兜底，连接卡死时宁可图晚到也先显示
（那条路同样带 `noanim`：没人等的动画比不动更烦）。
暗色主题压海报那一条原来写的是 `opacity: .94`，跟淡入抢同一个属性（未加载的图会被它顶成半可见），改成 `filter: brightness(.94)`。
实测：第一次插入的图 `opacity` 从 0 爬到 1 用时约 280ms；缓存图（`complete=true, naturalWidth=270`）当场就是 1。

两个池子的分工是实测出来的，不是设计偏好：

- 采集接口的"最近更新"流 `limit` 被硬限 20 条，内容又被 `中国动漫/内地剧` 占满（虎牙 20 条里 11 条是中国动漫），**电影在这个流里天然稀少**；带 `t=分类ID` 又只返回 0~2 条，所以"按分类列最新"这条路不通。
- 因此电视剧走 CMS 最新流（能拿到多源覆盖度），电影再补一批豆瓣「热门 / 新片」候选。
- 豆瓣 `j/search_subjects` 不返回上映日期，所以**只用于出候选、评分和海报**；"最近一年"一律以 CMS 的时间字段为准。豆瓣候选还要回查 CMS 命中才算数——这样点进去一定有结果。
- 归类是 `kind_of(CMS 的 type)` 优先、认不出来时退到豆瓣那条的 type（`row_kind()`）。这个兜底以前**走不到**：
  旧代码是 `if b["kind"]` 先过滤，kind 为空的行根本进不了 `pack_row`，于是 CMS 写着"现代都市"、
  豆瓣明确标了 tv 的那种行就被无声丢掉了（实测一批里有一条）。现在先算类别再筛，并且丢掉几条记成
  `dropped_kind` 写进标题。
- 列表接口 `ac=list` 常常不带 `vod_pic`，所以再用 `ac=detail&ids=` 批量回查补海报（`fill_pics`），否则卡片大片空白。
- **每一行把"每个源里这部片的 ID"都留着**（桶里的 `vids`，`pack_row` 打成 `sources: [{id, name, vid}]`）。
  以前只留 `probe` 那一对，结果猜你想搜的海报点开详情时**没有「换源看」**——面板不知道该换成哪个源的
  哪个 ID。豆瓣候选那条路也一样：`verify_pool` 探了好几个源，现在把每个源给的那对 ID 一并收下。
  `probe` 那个源排在最前，面板打开时选中的就是它；源改名或停用后取不到名字就退回显示 id。
  旧的 `hot.json` 里没有这个字段，所以那批行仍然只有一个源 —— 重建一次缓存就有了（6 小时到期自然重建）。
- TMDB：`api.themoviedb.org` 在本机网络超时，`api.tmdb.org` 可达但需要 API key，所以未接入。

构建一次约 100 秒以上，因此**绝不同步阻塞页面**：结果缓存在 `zhuiju/data/cache/hot.json`（6 小时），过期时请求立即返回旧缓存并标 `building: true`，后台线程重建；完全没缓存时先返回空并提示稍后刷新。

## 搜索结果的 SEO

每个关键词一个可被收录的固定地址：`/s/<关键词>`（如 `/s/%E5%BA%86%E4%BD%99%E5%B9%B4`）。

- 页面带 `title`、`description`、`canonical`、Open Graph，以及 JSON-LD：首页是 `WebSite` + `SearchAction`（告诉搜索引擎 `{{site}}/s/{关键词}` 是搜索模板），关键词页是 `ItemList`（含 `numberOfItems` 和每条结果的 `/s/` 链接）。
- **服务端渲染结果摘要**：爬虫不执行 JS 也能看到该关键词下的结果标题与链接；浏览器里 JS 自动接管成交互式界面，并把服务端摘要折叠成一行说明（`ssr-done`）。
- 结果快照在 `zhuiju/data/cache/seo-*.json`（6 小时），爬虫不必等并发检索，也不会每次抓取都敲上游接口；同一关键词的并发请求由锁去重。
- 搜过的关键词记入 `zhuiju/data/queries.jsonl`，`/sitemap.xml` 由「猜你想搜 + 历史搜索」生成——谁搜过某部剧，那部剧的 `/s/` 地址就会进 sitemap。
- `/robots.txt` 放行 `/` 和 `/s/`、禁止 `/api/`。

注意这仍是 127.0.0.1 的本地站点，要真被搜索引擎收录得先有公网地址；这套 URL 与元信息是为了让它能直接部署到可访问的地址上。

## 海报为什么走本站代理

第三方海报有两类问题，实测出来的：

- **防盗链**：`img*.doubanio.com` 无 Referer 返回 **418**、带本站 Referer 返回 **403**、只有带 `https://movie.douban.com/` 才 200。浏览器里伪造不了 Referer（`referrerpolicy="no-referrer"` 反而会让这些图全挂）。
- **证书 / 端口**：部分采集站图床挂在非标端口 + 自签证书上（如 `taopianimage.xyz:43333`），浏览器静默失败。

所以海报统一经 `/img?url=<原地址>` 取回：按域名补正确 Referer、忽略证书校验、只回传 `image/*`、限 3MB、并拒绝 `file:`/`javascript:` 等非 http(s) 与回环/内网地址（避免本机代理被打内网），而且只肯代理本站页面发出过的地址（`data/cache/img_urls.json`），否则挂到域名上就是一个人人可以驱使的公共图片代理。

### 海报缓存分三层

| 层 | 位置 | 活多久 | 管的是什么 |
| --- | --- | --- | --- |
| 浏览器 | `Cache-Control: public, max-age=86400` | 1 天 | 同一台设备刷新/翻页不回头问本站 |
| 进程内存 | `imgproxy._mem`（120 张） | 1 小时 | 这次请求根本不出门，连磁盘都不读 |
| 磁盘 | `zhuiju/data/cache/img/` + `index.json` | 7 天、上限 200MB | **重启之后还在**；换浏览器、换设备也不用各敲一次别人的图床 |

- 只有 `200 + image/*` 的应答才落盘；404、`text/html`、超大、被拒的地址一概不缓存 —— 否则一次上游抽风会被钉七天。
- 文件名就是 `sha1(地址)[:32]`，**不带扩展名**：类型只记在索引里，省掉"存的扩展名与算出来的不一致"这类错位；写都是先写 `.tmp` 再改名，半截文件不可能被当成命中。
- **索引必须与图片文件同步落盘**。第一版给索引加了 5 秒节流，结果"启动时清孤儿文件"的逻辑把那些还没来得及登记的文件当孤儿删了 —— 一次重启删掉 22 张里的大部分。现在 `_save_idx()` 每次写图后立刻落盘（几十 KB 的 JSON，跟一次 8 秒的上游抓取比是噪音）。
- 每张图是哪一层答的，写在响应头 `X-Img-Cache`（`cache` / `disk` / `fetched` / 拒绝原因）上，验证"重启后还快不快"不用猜。实测：冷取 `fetched` → 同进程再取 `cache` → **重启后同一张 `disk`**（耗时 ~20ms，不再出网）。
- 想关掉：`ZHUIJU_IMG_DISK=0`；想清空：直接删 `zhuiju/data/cache/img/`（整个 `data/cache/` 本来就在 `.gitignore` 里）。

另外 `ac=list` 列表接口常常不带 `vod_pic`（实测 36 条里 15 条没图），所以猜你想搜会用 `ac=detail` 按 `vod_id` 回查一次补海报；仍拿不到的，卡片用 `<img onerror>` 露出 🎬 占位符而不是留白。实测效果：猜你想搜 36 张里 **35 张成功加载**，唯一失败的是那个彻底连不上的图床。

## 海报上的「详情」按钮（点开才查，线路折叠在面板里）

每张海报右下角常驻一个小的**详情**按钮（结果卡片与猜你想搜都有；键盘 Tab 得到、有
`aria-label="查看《片名》的详情"`）。点一下从右侧滑出非模态面板：**导演 / 主演 / 年份 / 地区 /
类型 / 更新状态 + 简介 + 观看地址**，下面一排来源按钮：多个源时标签是「换源看」，
只有一个源时是「来源」并把那颗按钮点亮 —— 这一行说的是"这条详情是哪个源给的"，
不能因为只有一个源就整排消失（按片名兜底那条路进来时前端还不知道源，详情回来后会把它补上）。
点当前那个源不重开、也不重复上报，否则"看了一次详情"会被记成好几次。

几个刻意的取舍：

- **观看地址放在面板里，但一行一条线路，集数点了才铺。** 一部 36 集的剧一次插进 DOM 就是
  三十多个 `<a>`，面板会被撑成长条，而绝大多数没人点；所以 `linesHTML()` 只写线路名与条数，
  集数存在内存里的 `lineStore[id]`，第一次展开那条线路才把那一行的 `.eps` 插进去
  （`aria-expanded` 跟着变）。上一版这里是"点详情不给链接"（请求带 `meta=1`，本站把 `lines`
  剥掉再返回），后来确认不合适 —— 要看地址仍然得先点进页面，多绕一步；`meta` 这个参数因此
  整个删掉了，不留一条没人走、却又容易让人以为还生效的分支。
- **点了哪条观看地址会记进库。** 面板里点的记 `panel`，卡片里展开来源名点的记 `card`，
  见下面「详情与观看点击」一节。
- **绝不预取。** 详情数据只在点了按钮之后才要：面板先用卡片已有的信息（片名、年份、地区、主演、
  海报、覆盖源数）把内容铺出来，其余等一次 `ac=detail` 回来填，中间是骨架屏。
  `tests/test_detail.py` 用"渲染函数里不许出现 `detailURL` / `openDetail` / `getJSON`"钉住这一点。
- **不再劫持右键。** 上一版做的是海报右键弹自定义菜单，实测体验不对（右键在浏览器里本来就有
  保存图片、检查等操作），现在完全不用 `contextmenu`，页面上任何地方右键都是原生菜单。
- **卡片不再是整块一个链接。** 按钮不能嵌在 `<a>` 里，所以猜你想搜的结构改成
  `div.hotcard > span.hcover(封面 + 详情按钮) + a.hotlink(片名 + 元信息)`：海报负责详情，
  片名负责进页面。
- **两条来路，代价差一个量级。** 搜索结果每个来源都带影片 ID，一次 `ac=detail` 就够（实测 1–4s）；
  猜你想搜历史上只有片名，得先并发检索一轮才知道 ID —— 所以 `hot.py` 现在把 `(源, 影片 ID)`
  一起写进缓存行（`pack_row` 的 `src`/`vid`）。旧缓存里没这对值时前端自动退回按片名查，
  并在面板里写明"要慢几秒"。服务端对按片名的结果缓存 15 分钟，且**只缓存成功的**
  （失败多半是某个源此刻不通，把失败钉 15 分钟反而更糟）。
- **两条来路都有「换源看」。** 结果卡片每个来源都带影片 ID；猜你想搜那一行现在也带着
  `(源, ID)` 列表（见上面「猜你想搜」一节），两边点开的按钮里都放 `data-srcs`，面板才换得动。
  服务端渲染那份的 `data-srcs` 必须用**单引号**包：`{{ ... | tojson }}` 出来的 JSON 里全是双引号，
  用双引号包属性会顶穿，渲染出来的 DOM 直接是坏的（`data-srcs="[{`，后面全丢）。
- **重复开关不重复请求。** 前端按 `源:ID`（或 `片名`）缓存结果与在途请求，连点两次只发一次；
  切条目或关面板后，在途请求回来也不会填错地方（token 校验）；失败留一个「重试」并把缓存清掉。
- **面板非模态。** 开着它照样能翻页、搜别的片，Esc 或 × 关闭，焦点回到原处；窄屏（≤560px）
  面板铺满并锁住页面滚动。配色上按钮用 `--poster-ink` / `--poster-scrim` 这对**不随主题翻转**的
  token —— 它压在任意封面上，跟着 `--on-accent` 在暗色下会变成黑压黑（这条已进配色体检）。

`/api/detail` 的入参因此是：`?src=<源>&vid=<影片 ID>`（优先）或 `?kw=<片名>`（兜底）；
两个都给不上就 400，源停用则 404 并说明原因，不会偷偷去按片名查。返回里连着 `lines`
（线路名 + 逐集地址）一起给，折不折叠是前端的事。


## 详情与观看点击：搜完之后有没有人真去看

只记查询数分不出"搜一眼就走"和"真找到能看的"。所以两类点击都记：`POST /api/click`，
`kind=detail` 是点了海报上的**详情**按钮，`kind=play` 是点开了某条**观看地址**。
前端用 `navigator.sendBeacon` 发（没有就退 `fetch + keepalive`），**不 `preventDefault`** ——
点了就是要打开那个播放页，埋点不能把它挡住。

写进 `clicks` 表（和 `queries` 同一个 `stats.db`，同一条 `KEEP_DAYS` 界线清理）：
时间、`kind`、IP、关键词、片名、源、线路名、集名、目标 URL 与它的**域名**、`place`
（`hot` = 猜你想搜的海报、`card` = 结果卡片的海报或展开的线路、`panel` = 详情面板里的线路）、
UA 与认出来的浏览器/爬虫标记。域名单独存一列，因为"都点了哪些站"按域名聚合才有意义，整条 URL 太碎。
`detail` 那一笔本来就没有地址，所以 scheme 校验只作用于 `play`。换成另一个源等于又看了一次
详情，所以也记一条 `detail`；点当前那个源不记（它本来就不重开）。

后台不另开一张点击表，**点开行为就是明细里的行**，与搜索记录合在同一张表按时间倒序排：
`全部 / 只看搜索 / 只看点开` 三个胶囊切范围（`scope=all|query|click`），切换回第 1 页 ——
两边条数不一样，停在旧页码等于给人看空页。第一排的统计格 `详情 N / 观看 M` 直接跳到"只看点开"。

为什么不挂在搜索行下面展开：点开行为的关键词是前端带的片名，从「猜你想搜」海报点进来的人
**根本没搜过它**。实测库里 15 条点击按 `(ip, 关键词)` 能对上搜索记录的有 **0 条** ——
挂在搜索行底下就等于一条都看不见。合流以后"搜了 → 点详情 → 点播放"从上往下读就是过程。

- 一行里的列按两张表各自的含义复用：「来源页」对搜索是 Referer、对点开是 `place`
  （海报详情 / 卡片线路 / 猜你想搜），「入口」对搜索是 `via`、对点开是 `kind`（详情 / 观看地址），
  「关键词」那一格点开行写片名 + 源 + 线路 + 第几集 + 目标域名。
  搜索才有的数字（结果 / 原始命中 / 可用源 / 耗时）在点开行是 **NULL，渲染成破折号** ——
  写 0 会被读成"搜了没结果"。
- 筛选与聚合仍是 `click_stats()` 一次拿全（总量、独立 IP、按域名、按 `place`、按 `kind`），
  明细一次 `UNION ALL` 拿列表，都不按行发查询。
- 按「入口 / 来源」筛的是搜索那一侧的列，点开行没有这两列会被一起排除掉 ——
  这件事写在明细标题上，不静默少一半。

必须守住的边界（都有测试）：

- **`play` 只收 `http(s)`。** 这一列的值由客户端写，进后台是要当链接点的，`javascript:` 混进来
  就是自己给自己留 XSS；不是 http(s) 的一律不进库。
- **字段全部截断**（URL 300、关键词 60、片名 80、线路/集名 40、源与 ID 32），`place`/`kind`
  不在枚举里分别退回 `card`/`play`。
- **按 IP 限流**（默认一分钟 120 条，`CLICK_MAX` / `CLICK_WINDOW` 在 `app.py`），正文上限 16KB。
  这是个公开接口，不设上限等于邀请人拿脚本把统计库灌满；超了照样回 204 —— 回 4xx 只会让
  前端以为没发出去而重试。
- 已经建过 `clicks` 的老库没有 `kind`，也没有归属地与浏览器那六列：`ensure_schema()` 一次补完
  （`CLICK_COLUMNS`），再 `normalize_clicks()` 按留存的 `ip` / `ua` 回填一次，新老行才是同一套口径。
  老行本来就没存 UA，所以认不出来就按统一写法存成 `未知`（见「认不出来」那一节），不留 NULL；
  归属地库还没下载时**先不补** —— 补了就分不清"没解析过"和"解析成内网"了。
  读的地方再 `COALESCE` 兜一层，别让一个后补的列把聚合劈成两半。
- 这两张表的过滤条件共用一份 `_where()`（`clicks` 也支持 ip / 关键词 / 日期 / 浏览器 / 系统 /
  设备 / 归属地）：分开写两份迟早会漂，合成一张列表以后"按浏览器筛"必须两张表都筛得动。

播放页是第三方的，点开就跳过去了，本站只知道"点开了"，不知道最后看不看得成。


## 后台默认只看最近一周

日期什么都不选时 `/admin` 取**最近 7 天**（`ZHUIJU_ADMIN_DAYS` 可改，含今天），日期框里回填的就是
实际用的这个区间，页面上也写明"最近 7 天（起 ～ 止）"。不这么干用得越久这页越长，而"今天有没有
人用"恰恰是最想知道的。`queries` 与 `clicks` 吃同一把尺子（同一份 `_where()`、同一批表单值），
否则明细筛了最近一周、上面那几个统计格与下面的汇总却数的是全部历史。

出口是 `?day=all`：页面上那条「看全部历史」带上它，**翻页链接、筛选表单和跳转表单的隐藏域也跟着带**
—— 否则点一次"下一页"或筛个 IP 就会被默认值悄悄送回一周。反过来，URL 里显式给了 `day_from` /
`day_to` 时，默认值绝不顶掉它。

顺带修了一个真会 500 的地方：归属地没回填成的老行 `iso` 是 NULL，而模板写的是
`r.iso | default('') | length` —— Jinja 的 `default` 只管"键不存在"，不管值是 `None`，
于是那一页直接报 `object of type 'NoneType' has no len()`。改成 `(r.iso or '') | length`。


## hidden 必须真能藏住东西

浏览器自带的 `[hidden] { display: none }` 是 **UA 样式**，作者样式表里任何一条 `display:` 都压得过它。
本站的 `.pager { display: flex }`、`.statline { display: flex }`、`.dpanel { display: flex }` 就是这种，
于是首页明明没有搜索，「上一页 / 下一页」还是摆在那里 —— 而 JS 侧一切正常：`el.hidden` 读出来就是 `true`。
**这个 bug 从"属性"里量不出来**，只能量"它到底显不显示"（`getComputedStyle(el).display`、`offsetHeight`），
前一轮我就是只读了 `el.hidden` 就回去汇报"已修好"，所以连续两轮都没修对。
`.dpanel`、`.homebtn` 以前各打过一份 `[hidden] { display: none }` 补丁，漏掉的元素就继续复发。

现在换成一条全局规则（放在 `* { box-sizing }` 旁边）：

```css
[hidden] { display: none !important; }
```

带 `!important` 是因为要压过的作者规则形态太多（`flex` / `grid`，还有媒体查询里再改一次 `display` 的），
靠特异性一条条追是追不完的；`hidden` 的语义就是"不许显示"，不该有例外。那两份各别补丁同时删掉，
不留同一个机制的两套写法。

回归检查是扫全页：把 `document.querySelectorAll('*')` 里所有 `el.hidden === true` 的元素过一遍，
计算样式不是 `none` 的全列出来 —— 实测首页、搜索出结果、详情面板打开、线路集数折叠这四种状态下
都是 0 个。同时确认"该显示的"还在：搜索时 `#pager` = `flex`、`#statline` 那四个标签始终在、
折叠着的 `.lbody` = `none` 且高度 0；1500 宽下 `scrollWidth - innerWidth` 仍是负的（没有横向溢出）。

顺带一条同类发现：站点在两轮修改之间**进程死掉过**（`logs/server.out` 停在 10:40:55，5000 端口没人监听），
`restart.py` 是用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 起的手工分离进程，但它仍然会随
上一轮 CLI 进程树结束而没了。所以"改完没生效"先要确认的其实是**站点还在不在**：
`python tools/restart.py` 会先杀干净监听者再起来，并用"只有当前这版代码才有的特征路由"判就绪。

## 手机 / 平板适配

改法是靠量的，不是靠猜的：把首页、结果页、后台面板分别塞进 **320 / 360 / 390 / 768 / 1440**
五档 iframe（媒体查询按 iframe 自己的视口算），量完再改，改完复量。四组数：

| 量什么 | 改之前 | 改之后 |
| --- | --- | --- |
| 320px 屏上留给内容的净宽 | 249px（`.wrap` 是 `100% - 48px` 再左右各 24px 内边距，31% 的屏被边距吃掉） | 285px（360→325、390→355、768→657） |
| 小于 12px 的文字 | 91 处（11 / 11.5px 的次要信息） | 0 处 |
| 高度不足 30px 的可点元素 | 22 处（海报角上那颗「详情」只有 37×19px） | 0 处（详情按钮 44×32，片名 44，后台表格里的链接 17→31） |
| 文档横向溢出 | 首页 377>360 能横着拖；后台 360 溢 100px、390 溢 70px | 全部 0 |

具体做的几件事：

- **把宽度还给内容。** ≤640px 时 `.wrap` 改成整宽只留 10px 内边距；四个标签不再各自换成 98px
  高的砖，而是一行横滑（`.tabs` 内部 `overflow-x:auto`，滚动条藏掉）。后台那些表也是同一类问题：
  表在滚动框里还被 `width:100%` 挤着，而中文能按字折行，十二列的明细在 320 上一行撑到
  151px 高、字全竖着排。改成 `.fold table { width: max-content; min-width: 100% }` 之后
  行回到 31px（合流以后点开行与搜索行同一张表，320 上实测 15 行全是 31px），多余的去横向滚 ——
  横向滚动是看得见的，竖着排的字是读不动的。
- **小字号与输入框字号都走 token**（`--fs-min` / `--fs-sm` / `--fs-input`），窄屏只抬 token。
  `--fs-input` 是为了 iOS：聚焦字号小于 16px 的输入框时 Safari 会把整页放大且缩不回去，
  后台那些 12.5px 的筛选框必须抬到 16px。
- **触摸目标按用途给，不是一刀切 44px。** 访客用的猜你想搜片名给到 44；后台表格里那些筛选链接
  和结果没回来那几秒显示的那份给爬虫的列表（`.ssrlist`）都用"内边距 + 等量负外边距"撑开
  （表格链接 17→31，列表链接 17→34）—— 实测行高一个像素没变（31/31/30/31/31，整表 122px，
  加这条规则前后一样），只是按得准了。
- **手机上面板改成底部抽屉**（≤560px）：铺满整宽、限高 `86vh`、从下面推上来、`padding-bottom`
  带 `env(safe-area-inset-bottom)` 躲开 home indicator，打开时锁住页面滚动，关掉即解锁。
  **进出要对称**：宽屏从右边滑进 / 滑出，窄屏从下面推上 / 推下，都是同一个 `.dpanel` 的
  `transform` 过渡（`.26s`），方向由 CSS 决定，JS 只管切 `.on`。以前"进来"是直接出现的 ——
  因为 `dpEl.hidden = false` 和 `dpEl.classList.add('on')` 写在同一帧里，浏览器从没算过
  "还在屏幕外"这个起点，没有起点就没有过渡（关闭方向反倒一直是好的，所以看着像"滑出、蹦进"）。
  现在两句之间插一次 `void dpEl.offsetWidth` 强制布局，把起点算出来；关闭那边也不写死时长，
  读面板自己的 `transition-duration` 再延 40ms 才 `hidden = true`（抄一份数字的话，CSS 改时长
  这边就悄悄不一致；用 `transitionend` 则会被子元素冒泡的过渡干扰，而且 reduced-motion 下
  `transition: none` 永远等不到事件）。
  抽屉里的观看地址同样是一行一条线路、点了才铺集数（360 上实测：展开一条 36 集的线路，
  集数格子 67×34，没有一个是够不着的触摸目标，文档横向溢出仍然是 0）。
- **登录那张卡片在手机上也改成整宽**。`口令 + 进入` 原本是横排，320 上卡片内宽只剩 253px，
  flex 把按钮压成 42×51（"进入"两个字换了行）；≤560 改成各占一整行，输入框吃满（235×43）、
  按钮 235×40。561 以上仍是横排 —— 360 上卡片内宽 293，本来就放得下，没必要竖着。

踩过的四个坑，都写进测试了（`tests/test_agent_theme.py` 第 11 节，28 条）：

1. 覆盖规则必须留在**文件最后**。同优先度的规则按先后取胜，第一次把窄屏那段写在中间，
   字号看着改了、量出来还是 11.5px。
2. **媒体查询不加特异性**。`input { font-size:16px }` 是 (0,0,1)，压不住 `.admfield input`
   的 (0,1,1) —— 所以真正起作用的是 token，兜底那条只是给没走 token 的控件用的。
3. **flex / grid 项默认 `min-width:auto`**，不肯缩到比内容更窄：四个不换行的标签能把整个文档
   顶宽（不是标签条自己横滚），后台收成单列后一长串 `python -m ...` 命令也能顶宽。
   解法都是 `min-width: 0`，让该横滚的那层（`.tabs`、`.fold`）自己去滚。
4. 断长 token 要用 **`overflow-wrap: anywhere`**，不是 `break-word`：只有 `anywhere` 参与
   min-content 计算，`break-word` 写得再对也照样把列顶宽。

复量的办法没留在仓库里（探针页是会被人访问到的，量完就删了）：在站点任意页的控制台里
`document.createElement('iframe')` 设成 320/360/390/768/1440 宽指向 `/`、`/s/庆余年`、`/admin`，
媒体查询按 iframe 自己的视口算，量 `documentElement.scrollWidth - clientWidth`、每个 `a/button/input`
的 `getBoundingClientRect().height`、以及计算样式里小于 12px 的字号。后台面板要连着数据一起量，
就先在服务端把 `/admin` 渲染成快照再剥掉 `<script>`（折叠高度是 JS 量的，量布局不需要它）。
注意别把窗口缩到 900 以下来"假装手机"——那连的是窄桌面，`hover: none` 那些行为不一样。


## 数据自动更新（访问时触发）

不使用系统计划任务。判据是 `zhuiju/data/refresh_state.json` 里"**当天**有没有成功更新过"，而**"当天"以凌晨 2 点为界**（`ZHUIJU_REFRESH_HOUR` 可改）：

```
01:30 访问  ->  仍属上一个周期，不触发
02:00 访问  ->  新周期开始，当天没跑过才触发
23:00 跑过  ->  次日 01:00 访问不重跑，02:05 访问才会再跑一次
```

按自然日会有两个毛病：凌晨 1 点访问就把"今天"的更新跑掉、2 点后又会再跑一次；反过来 23 点跑过的，次日 00:30 访问会被判成"没更新"而白跑一趟。`tools/refresh.py` 写标记用的是同一个 `logical_day()`，两边口径一致才不会重复触发。

- 打开网站时（请求 `/` 或 `/sitemap.xml`）检查一次，需要更新就**丢一个独立进程**去跑 `tools/refresh.py`，
  请求本身不等待，因此**这次照常返回上一次的数据**。
- 页头横幅按真实情况分六种措辞与颜色，不把"陈旧"说成"失败"：

  | 状态 | 颜色 | 页头显示 |
  |---|---|---|
  | `fresh` | 绿 | `数据 10-15 14:41 自动更新 · 检索源 10/10`，副文案带上游目录版本 |
  | `running` | 黄 | `正在后台更新（第 5/6 步：验证各站搜索路径）` + 进度条 + 六个步骤胶囊 |
  | `partial` | 黄 | `上次只跑了快版（14:41，跳过 deep、merge…）`，提示访问时会补跑全量 |
  | `stale` | 红 | `数据是 2026-10-12 更新的，已过当天周期` |
  | `failed` | 红 | `上次自动更新有步骤失败（health、verify）`，副文案指向 `logs/refresh-*.log` |
  | `never` | 红 | `尚未自动更新过` |

- **进度是实时轮询出来的**：`tools/refresh.py` 每开始/结束一步就把 `done/total/step_label/steps[]/note`
  写进 `zhuiju/data/refresh_progress.json`，页面在 `running` 状态下每 3 秒读 `/api/refresh`，
  更新进度条与步骤胶囊；跑完把横幅变成"数据已更新完成"并给出「刷新页面查看」链接。
  步骤清单只有一份（`autoupdate.STEPS`），`refresh.py` 和页面都从它取，不会两边对不上。
- **"是否在跑"以锁文件里的子进程 PID 为准**，进度文件只补充细节。子进程刚拉起、
  还没写第一个进度文件时页头也已经能说"正在后台更新"；子进程崩了而进度文件还停在
  `running: true` 时，`running()` 用 WinAPI 探活识破并清锁，不会一直谎报进行中。
  进程活着就不受 `LOCK_TTL`（25 分钟）约束——单个步骤最坏 15 分钟，用超时推翻"进程明明还在"
  会多起一个更新进程。
- 锁文件 `logs/autoupdate.lock` 记录子进程 PID；更新进行中重复访问不会再启动第二个。
  今天更新**失败**、或只跑过 `--skip-deep` 快版时，再次访问会重新触发完整一轮——
  但失败的要等冷却过去：一轮刚失败（状态里有 `finished_at`）后的 `ZHUIJU_RETRY_MINUTES`
  （默认 15）分钟内不再自动重跑。失败大多是环境性的（解释器不对、依赖没装、出网被挡），
  这种时候只要有人访问就重跑一遍注定失败的六步，等于每分钟敲一次第三方接口并灌满 `logs/`。
  冷却对"读不出 `finished_at` 的老状态文件"不算数（不猜，直接允许重试）。
- 更新写完文件后，站点按 mtime 重新读取，**不用重启服务**就能看到新数据。
- 更新过程逐步写入 `logs/refresh-*.log`（保留 14 份），长跑期间也能看进度。日志开头两行
  写明了**跑各步骤用的解释器以及选它的理由**——"六步全挂且 `seconds` 只有 0.1"这种就一眼能看出来。

一次更新做的事：拉上游目录（走 gh-proxy）→ 体检所有检索源并写回 `enabled`/`browsable` →
从 TVBox 配置补抽新接口 → 并入实测可用的 → 双关键词验证各站搜索路径 → 写入模板。
整套约 8 分钟；只想快点走完可加 `--skip-deep`（这种快版不再算"本周期已更新"）。手动执行：
Windows 双击 `refresh.bat`，或 `.venv\Scripts\python.exe tools\refresh.py --force`；
Linux 用 `sh refresh.sh --force`。想先确认环境对不对，加 `--check-env`（只报解释器和依赖，不跑）。

跑之前有一道 preflight：解释器不存在、或者里面没装 `flask/requests`，就直接把这句话写进状态
和日志并结束（`failed_steps: ["env"]`），不会让六个步骤各抛一遍 `Exec format error`。

### GitHub 数据一律走国内镜像

上游目录与 TVBox 配置都在 GitHub raw 上，直连在国内基本拉不动。`tools/build_catalog.py`
按 `MIRRORS` 顺序试：`gh-proxy.com` → `ghproxy.net` → `ghfast.top` → `mirror.ghproxy.com`
→ 最后才是 `raw.githubusercontent.com`，并把这次真正用到的镜像写进
`zhuiju/data/cache/mirror_used.json`，同时回填到进度里，页头副文案因此能说清
`上游数据源：gh-proxy.com（149889 字节）`。本机 pip 依赖用清华源（见"国内环境准备"）。

注意 `upstream()` 每次都会重新下载，本地文件只当镜像全挂时的兜底——之前"本地有文件就跳过"
让每天的"拉上游目录"实际是个空操作。

验收这套机制：`.venv\Scripts\python.exe tools\check_autoupdate.py`（用桩替换真实更新，
九个场景：不该触发时不触发、该触发时启动、期间仍可搜索、重复访问只起一个、
进程死了要识破、失败后要重试、横幅措辞对得上、进度以子进程存活为准、
**失败冷却期内不重跑**、**解释器是现找的**）。
测试的状态/进度/锁文件全在 `.probe/autoupdate_test/`，不会污染真实数据。

跨平台那部分另有 `.venv\Scripts\python.exe tests\test_deploy_paths.py`：在 Windows 上把
`is_windows()` 换成假值来验 Linux 的候选顺序，再造一棵假 `/proc` 验端口归属的解析
（真 `/proc` 和 socket 软链接在 Windows 上造不出来，不注入就没法测——这条测试确实抓出过一次
"参数写了但函数里没用它"的错）。

## 后台统计（/admin）

打开 http://127.0.0.1:5000/admin ，要口令。

### 口令在哪改

**第一次登录会自动带你去改口令。** 文件不存在时首次启动会随机生成一个 12 位口令（打印在控制台一次），
并在 `admin.json` 里标 `"password_is_temp": true`；用这个随机口令登录成功后，不会直接进统计页，
而是跳到「先设置一个你自己知道的口令」，输入当前口令 + 新口令两遍，**保存即写回配置文件、立刻生效，
不用重启服务**。改完标记变 `false`，以后登录就直奔统计页；页面上也留着「改口令」入口随时可以再改。

`zhuiju/data/admin.json`：

```json
{
  "password": "你自己定的口令",
  "secret_key": "随机 64 位串，用来签登录 cookie",
  "password_is_temp": false
}
```

想手动改也行：编辑 `password` 再重启（`secret_key` 那行别动，动了所有已登录会话都失效）。
老配置文件里没有 `password_is_temp` 这个键时，会按口令长得像不像随机生成的判断一次并写回文件。

新口令最少 6 个字符、不能首尾带空格；当前口令必须验对才能改（过期会话不能替你改），
两次输入不一致、太短、为空都会被拒且不会写进文件——空口令会让 `load()` 又生成一个随机的，反而更迷惑。

也可以用环境变量 `ZHUIJU_ADMIN_PASSWORD` 覆盖，让明文不落盘；这种方式下页面**不会**催你改口令
（本来就打算靠环境变量部署的人，改文件不会生效），改口令页会明确提示当前口令由环境变量指定。
`ZHUIJU_SECRET_KEY` 同理。

这个文件和统计库一样进了 `.gitignore`——里面是明文口令，不该提交。

### 统计了什么

每次真正敲上游接口的查询记一条，存 SQLite（`zhuiju/data/stats.db`，标准库 `sqlite3`，无额外依赖）：

| 字段 | 含义 |
|---|---|
| `ts` / `day` | 时间戳与日期（按日期范围筛就用 `day`，含两端） |
| `ip` | 客户端 IP |
| `kw` | 关键词 |
| `via` | `api`=页面搜索 / `seo`=落地页快照 / `cloud`=网盘查询 |
| `results` / `hits` | 合并去重后的条数 / 各源原始命中之和 |
| `sources_ok` / `sources_total` | 本次有多少源真的返回了 |
| `ms` | 这次等了多久 |
| `iso` / `country` / `geo` | 国家码、国家名、完整归属地文案；内网/保留地址的 `iso` 是空串 |
| `browser` / `os` / `device` | 从 User-Agent 认出的浏览器+版本、系统、手机/平板/桌面/程序 |
| `bot` | 1=爬虫或脚本客户端（curl、requests、Googlebot…），与真人分开数 |
| `ua` | 原始 UA（截断 200 字节），认错了要能回查 |
| `ref` / `ref_kind` / `ref_label` | 来源：站内是完整路径，站外只有域名；类型 `site`/`search`/`out`/`direct`/`other` |

同一个库里还有第二张表 `clicks`（行为日志：谁、用哪个词、哪部片、点了详情还是某条线路的第几集、
跳去了哪个域名、从哪儿点的），字段与它的边界见前面「详情与观看点击」一节；
两张表按同一条 `KEEP_DAYS` 界线一起清理。

### 浏览器识别

只用标准库认，没引第三方 UA 库（清华源上有 `ua-parser` 之类但没必要为这一列多加依赖）。
覆盖 Chrome / Edge / Opera / Firefox / Safari / IE / 三星 / Vivaldi / Electron，
以及国内常见的微信内置、QQ浏览器、UC、夸克、360、搜狗，外加爬虫与命令行客户端。
**顺序是关键**：Edge、Opera、微信的 UA 里同时带 `Chrome/xxx` 和 `Safari/604.1`，
先判 Chrome 就会把它们全认成 Chrome；Safari 那条也因为这个必须排在最后。
iPad 的 UA 里带 `Mobile/15E148`（苹果为兼容老站点留的历史标记），所以不能靠有没有
`Mobile` 来区分手机和平板，iPad 要单独认。

要当它是"大致构成"而不是精确计数：UA 由客户端自己写，可以随便伪造；国产壳浏览器
（360、搜狗、各家双核）也经常不自报身份，认不出就写"未知"，不猜。

**"认不出来"在库里只有一种写法。** 补列之前那批行 `browser/os/device` 是 NULL（那时根本没存
UA），现在的写法是 `未知` / `''`；两套混在一张表里，「浏览器 / 设备」就会把同一个"未知"
显示成两行（本机真实数据撞上过：`未知·—·未知` 16 次与 `NULL·NULL·NULL` 9 次），点进去的
筛选条件又只命中其中一套，数字对不上比数错更难查。所以：`ensure_schema()` 里 `normalize_agent()`
把 NULL 归成新写法（幂等，原始 UA 留在 `ua` 列不动，那批行本来就是空串，确实无从判断）；
聚合与 `_where()` 里"未知"这个桶也顺手把 NULL 与 `''` 一起算上，备份恢复出来的老库就算
还没跑过迁移，面板与点进去的数量照样一致。

### 来源页（对方从哪来）

取自 `Referer` 头。**能给多少由浏览器的 Referrer-Policy 决定，不是我们能控制的**，
默认策略 `strict-origin-when-cross-origin` 的实际行为是：

| 场景 | 浏览器给什么 | 这一列显示 |
|---|---|---|
| 站内跳转（同源） | **完整 URL** | `站内 /s/庆余年`（能看到上一页具体是哪部剧） |
| 跨站跳转 | 只给 `协议://域名` | `https://movie.douban.com`（路径被抹掉，拿不到就不编） |
| 搜索引擎点进来 | 只给域名，但查询词在 URL 参数里 | `百度 搜索「春风烈马」进来` |
| https → http | 什么都不发 | 归到"直接访问" |
| 手输地址 / 书签 / 新标签页 | 什么都不发 | `直接访问 / 无来源` |

所以"直接访问"那一类里混着好几种情况，分不开就不硬分。这个头同样可伪造。
站内判定用的是 `request.host` + 去端口主机名 + `127.0.0.1` + `localhost` 一组口径；
`localhost` 和 `127.0.0.1` 在浏览器眼里是两个不同 origin，只有都登记成本机地址时才算站内。
搜索引荐认 Google / 必应 / 百度 / 搜狗 / 360 / 神马 / DuckDuckGo / Yandex / Yahoo，
各家参数名不同（`q` / `wd` / `query` / `p` / `text`）。

历史行在这两批列加上之前是没有数据的，页面显示"未知 / 未解析"，不做任何猜测性回填
（归属地可以凭 IP 事后算，UA 和 Referer 是当时那一个请求才有的信息，错过就没了）。

### 真人、脚本，还是说不清

只有 UA 那一列是分不出来的：UA 是客户端自己写的，`curl` 会写 Chrome 也照样收进来。所以这里分两层，
而且明说每一层的边界。

**第一层是三档徽章（`stats.WHO_SQL`，一个 SQL 表达式，全站唯一口径）**：
`bot` = 写库时 `agent.BOTS` 命中（curl / wget / python-requests / python-urllib / python-httpx /
go-http-client / okhttp / scrapy / headlesschrome / werkzeug / 各家搜索引擎爬虫…）；
`unknown` = **无从判断**：当初没存 UA、`bot` 是补列之前的 NULL，或者 UA 根本不长浏览器的样子
（不以 `Mozilla/` 开头）；`human` = UA 有浏览器骨架且没自报爬虫，**这不代表确认是人**。
第三档那两条判据各管一头：`SUM(bot)` 会把 NULL 当 0 吃掉，不写"说不清"这一档"含程序 N"就被系统性低估；
而只靠"UA 里没写 curl 就算人"会漏 —— 实测有 27 条 `Werkzeug/3.1.9`（Flask test_client 自带 UA，
离线工具 `check_autoupdate.py` 每跑一次往真实库里写一行）顶着"浏览器 未知"被判成"像真人"，
页面上一行里自相矛盾。用 `Mozilla/` 开头而不是 `like Gecko` 判骨架，是因为 **Firefox 的 UA 里是
`Gecko/20100101`、没有 `like Gecko`**，写后者会把真 Firefox 冤枉成说不清。
同一行的另一件事要分清：**「浏览器 未知」只代表我们的词表没命中**，不等于不是真人（有 `Mozilla/5.0`
骨架就仍算像真人）；反过来认得出 Chrome 也不保证是人。
筛选栏的「像谁」、汇总第一排那一格、明细每行的徽章、`summary.by_who` 全都走同一个表达式，
不会出现"面板合成一行、点进去少几行"（那是「认不出来」那一节踩过的同一个坑）。
`tools/check_autoupdate.py` 也和它对状态文件做的一样，把 `stats.DB` 指到 `.probe/` 下，
离线工具从此不再往真实统计库里写测试记录（改完实测：跑前 106 条、跑后仍 106 条）。

**行为那一节的判读理由会同时挂到明细每一行的 IP 旁边**（`.behflag`，虚线琥珀色小胶囊，写的是短文
「秒级连发 / 节拍器 / 无站内跳转 / 从没点开」，整句话连同那三个数在 `title` 里）。为什么值得挂两处：
行为特征是**按 IP** 算的，而人翻的是明细那一长串，来回对照很痛苦。UA 自报的那两种不重复挂 ——
每行右边本来就有三档徽章，同一件事不说两遍；`behavior()` 因此给每条理由标了 `src`（`ua` / `act`），
模板按它决定挂哪几种，而不是在模板里再抄一份 key 清单。

**第二层是「像脚本的行为特征」（`stats.behavior()`，按 IP）**，问的不是"它说自己是什么"而是"做出来的样子像不像人"：

| 指标 | 怎么算 | 抓得住什么 |
| --- | --- | --- |
| 最快间隔 / 平均间隔 ± 标准差 | 窗口函数 `LAG` 取相邻两条搜索的时间差；标准差在 Python 里开方 | 秒级连发；每次都隔一样久的"节拍器" |
| 变异系数 `×n` | 标准差 ÷ 平均值（≤ 0.25 且间隔数 ≥ 8 判为节拍器） | 定时器式访问，人做不到这么稳 |
| 峰值 / 分 | 把 `ts` 截到分钟纯文本分桶取最大 | 并发抓取 |
| 站内跳转 % | `ref_kind = 'site'` 的占比（爬虫通常没有上一页） | 从不浏览、只打接口 |
| 点开比 | `clicks` 条数 ÷ 搜索条数（同一个 IP、同一套筛选） | "搜了但从没点开"的扫描器 |

**判读是"提示"不是打分**：每条理由（`ua-bot` / `ua-none` / `burst` / `metronome` / `no-ref` / `no-click`）
都对应页面上某一列的数，能当场复核；不做"综合可疑度"那种说不出来源的数字。理由多的排前面。
反过来也要承认边界，页面那段说明写得很直白：脚本只要老实带上 Referer、按秒随机休息，这几列就看不出来 ——
真要钉死只有一条路，给首页发一个**匿名会话 token**（只存随机数、不落身份信息的 cookie），
`/api/search` 不带它就记成脚本。那是加 cookie 的决定，涉及合规，所以留到真被外部滥用的时候再说；
现在这站点还是 `127.0.0.1`，全库只有一条 IP 的行为特征行（就是这台机器 + 我做验证留下的痕迹）。

两个实现坑顺手记下：SQLite 这边没编数学函数（`sqrt` 不存在），所以 SQL 只给 `n / sum / sumsq`，开方在
Python 里做；只有一个 IP 只有一条搜索时，`LAG` 那组一行都不返回，取 `d["sumsq"]` 会直接 `KeyError`，
所以那几个间隔指标都要先补默认值（`tests/test_admin_stats.py` 第 24 节把这两种情况都钉住了）。

### 主题（亮 / 暗 / 跟随系统）

标题旁的按钮点一下在 **跟随系统 → 亮色 → 暗色** 之间循环，选择记在 `localStorage`，
两个页面（首页与后台）都有。默认是"跟随系统"，选"跟随系统"时还监听系统配色变化，
切了立刻跟着变。

实现上有两点值得记：

- 调色板**只靠自定义属性**：先把散在规则里的 24 处写死浅色值抽成语义变量
  （`--ok-bg`、`--bad-line`、`--sea`、`--on-accent` …），亮色取值一字未改，
  然后 `[data-theme="dark"]` 里整组覆盖一遍并声明 `color-scheme: dark`
  （表单控件、滚动条、原生日期选择器才会跟着变）。加新组件时只要用变量写颜色，
  两套主题就自动都成立。
- 主题必须在样式表加载前就定下来，否则暗色用户每次刷新都会闪一下白。
  所以 `templates/_theme.html` 是**内联**在 `<head>` 里的读值脚本，不能改成 `defer`
  或外链（那样要等一次网络往返）。副作用是完全禁用 JS 时拿不到系统偏好，
  会固定在亮色——这个站点去掉 JS 本来就没有搜索界面，所以是笔划算的取舍。
- 切换是**渐变**的，但过渡只在切换那 0.34s 里临时挂一个 `.theme-anim` 类，之后立刻摘掉。
  写成常驻的 `* { transition: … }` 会把 hover/focus 原有的短过渡全拖成 300ms，
  长表格里滚动还会掉帧。`prefers-reduced-motion: reduce` 时完全不渐变。
  首屏不走这条路径（由预置脚本直接定色），所以打开页面时不会先闪一遍。

### 配色体检

`tests/test_agent_theme.py` 第 8 节直接把 CSS 调色板里的颜色配对算 WCAG 对比度
（`--on-accent`/`--brand`、`--dim`/`--surface`、`--ok`/`--ok-bg` 等九对，亮暗各算一遍），
低于 4.5 就报错。它是查出来的第一批问题：

| 位置 | 原来 | 现在 |
|---|---|---|
| 主按钮（搜索/筛选/进入） | 蓝底上写红字（`color: var(--bad)`，一次批量替换的失误） | 白字，5.01 |
| 次级文字 `--dim` | 2.98，11–12px 的小字基本看不清 | 4.77 |
| 成功 / 警告 / 失败文字 | 3.31 / 3.32 / 4.16 | 5.41 / 5.25 / 4.79 |

`.gobtn`、`.reset`、`.pbtn`、`.pager a`、`.jumpbtn`、`.themebtn`、`.fbtn`
原本是七份几乎一样的规则（各写一遍圆角和 hover），现在合并成一条，
圆角与输入框统一（胶囊 99px、按钮 8px），次级动作一律淡底 + 悬停转品牌色，
不再用红色暗示"危险"（清空筛选不是删库）。输入框背景从 `--surface` 换成 `--surface-2`，
在白卡片上才有边界。

### IP 归属地与世界地图

**要先下数据**（约 14MB，走 gh-proxy 镜像，一次性的）：

```bat
.venv\Scripts\python.exe tools\fetch_geo.py
```

没下也不影响使用：归属地列会显示"未下载归属地库"，地图那一块给出上面这条命令。

| 文件（都在 `data/geo/`，已 gitignore） | 大小 | 用途 |
|---|---|---|
| `ip2region_v4.xdb` | 10.6MB | IP → `国家\|省\|市\|ISP\|ISO`，55 万网段 |
| `ne_110m.geo.json` | 0.8MB | 画地图的国家轮廓 |
| `ne_50m.geo.json` | 2.9MB | 只用来算国家坐标（110m 缺新加坡、马耳他等小城邦） |
| `country_points.json` | 几十 KB | 算好的 ISO → 经纬度，246 个国家 |

解析完全**离线**、只用标准库：实测清华源上没有 `ip2region` 这个包，而 xdb 格式本身很简单，
自己读（`zhuiju/geoip.py`）反而少一个依赖，也不用把访客 IP 交给任何第三方接口。
查询算法对着 20 个已知 IP 验过（1.1.1.1→AU、223.5.5.5→中国浙江杭州、8.8.8.8→US 等）。
`tools/fetch_geo.py` 每次跑完还会报告"库里的国家码有几个在坐标表里找不到"，当前是 0。

地图是**内嵌 SVG**，不引 Leaflet、不接瓦片服务：那要连境外 CDN（这台机器上不可靠），
而且等于把访客 IP 泄露给第三方。投影用等距圆柱（`viewBox="0 0 360 180"`，`x=经度+180`、
`y=90-纬度`），轮廓路径来自 110m（约 115KB，精度取 0.1°，肉眼看不出但体积小一半），
**有查询记录的国家会被单独描色**，圆点半径按 `sqrt(次数)` 缩放（面积才与数量成正比，
线性放大半径会让大国糊满整张图）。点圆点或表格里的国家名 = 只看这个国家的查询。

国家坐标按"最大那个多边形的面积加权形心"算，不是所有点取平均：俄罗斯、美国、澳大利亚
这种带飞地/跨半球的国家，平均点会被拖到海上去。踩过的坑：澳属外部领地（Ashmore and Cartier
Islands 之类）的 `ISO_A2_EH` 也是 `AU`，按写入顺序会让澳大利亚的点落到海里那块小岛上——
所以同一个国家码只保留**面积最大**的那个要素，结果与遍历顺序无关。

不属于公网的地址**不上图**，也不去查库，按语义分开标注：`本机`（127.x/::1）、
`内网`（10.x、192.168.x、172.16-31.x）、`保留地址`（组播、链路本地、CGNAT 100.64/10、
基准测试 198.18/15，以及 203.0.113.x 这类文档用例段）。这里有个容易忽略的细节：
Python 3.13 把文档用例段也算进 `is_private`，若先判 private 就会把 TEST-NET 说成"内网"，
所以判定顺序是先排除保留段、再判内网。

统计页因此默认只会有"本机/内网"一行——服务只听 127.0.0.1 时本来就该如此，
地图上有国家分布的前提是 `--host 0.0.0.0` 或挂 nginx 反代（后者才会认真读 X-Forwarded-For）。

页面还会多一块「国家 / 地区」表（国家名 / 次数 / 独立 IP / 关键词数 / 最近日期）。**这一列只显示国家名**（库里的 `country` 列：中国 / Australia / United States），省市与运营商只在明细行的完整文案里出现——早先拿整条 `geo` 文案当分组标签，列表里就会冒出「中国 浙江省杭州市 · 阿里」这种地区级内容，看着像分组错了，
筛选表单多一个「国家码」输入框，填 `--` 就是筛内网与保留地址。
老库升级时会自动补 `iso`/`geo` 两列并把历史记录回填一遍，之后不再重算。


内容宽度按屏走：`min(1680px, 100% - 48px)`，1366 / 1600 / 1920 的 16:9 屏上分别占 95% / 96% / 88%，
超宽双屏靠 1680px 上限挡住，不至于把一行表格拉到没边。猜你想搜的列数也跟着屏走：
≥1500px 9 列、1240–1499px 7 列、默认 6 列，窄屏再降到 5/4/3/2。

页面分九块：汇总卡片（查询次数、独立 IP、独立关键词、零结果及占比、平均可用源、平均耗时、
详情/观看点击、**像真人 / 说不清 / 脚本 三档**）、
按天（点某天=把范围收到那天）、热门关键词、活跃 IP（点 IP=只看这个 IP）、
浏览器/设备、来源页、**像脚本的行为特征（按 IP）**、明细表、
**IP 归属地地图（放最底下，日常翻明细用不上，不占首屏）**。
筛选表单支持 起始/结束日期、IP、国家码（填 `--` 就是内网/保留）、关键词包含、入口、**像谁（三档）**、
每页 25/50/100/200；**所有条件都走参数化 SQL，翻页链接会带上当前条件**。

明细翻页不整页重载：点上一页/下一页、点「全部 / 只看搜索 / 只看点开」切范围，或在「跳到 __ 页」里输页码，
只重新拉取并替换 `#detail` 这一块（`fetch` + `DOMParser`），地址栏用 `history.replaceState` 同步。
没 JS 时这些链接与表单仍是普通 GET 请求，功能不坏，只是会回到页顶。页码输入框带 `min/max`，
越界会被夹到首页/末页（前后端各夹一次）。
**页面一步都不滚**：明细自己就是个固定高度的滚动框（见下），换进来的是全新的框元素、
`scrollTop` 天生是 0，新页自然从第一行开始，外面原来停在哪儿就还停在哪儿。早先这里做过一次
「翻页后把明细滚回视野里」的定位（`scrollIntoView` + `#detail { scroll-margin-top }`），当时明细
整块摊在页面上，翻一页就得重新滚下来；现在框内滚动，这个定位反而会把人甩到别处，所以整段删掉了。

每块表都固定在自己的高度里滚，而不是把整页拉长：按天 / 热门关键词 / 活跃 IP / 浏览器·设备 /
来源页 / 像脚本的行为特征 / 国家·地区 只露 **5 行**，明细只露 **10 行**，剩下的在框内用滚动条看（`.fold { overflow: auto }`，
没有展开/收起按钮）。**按天是最新一天在最上面**（SQL 本来就 `ORDER BY day DESC`，早先是页面里
`list(reversed(...))` 又翻了一次，所以越近的天越沉在下面）——"今天有没有人用"要看的就是第一行。
三个不显然的点：

- **框高不是写死的像素。** 行高会随折行变化（来源格、浏览器格经常换行），写死就露半行，
  所以由脚本量第 N+1 行的 `offsetTop` 来定，且**设完高度再量一次**：竖向滚动条占掉宽度会让行
  重新折行，横向滚动条占掉高度会把最后一行压在上面，两笔都得补偿。行数不足 N 时不设高度，
  也不会有滚动条（`scrollHeight == clientHeight`）。窗口宽度变了防抖 200ms 重算。
- **框内滚动时表头吸顶**（`position: sticky`），分隔线用 `inset box-shadow` 而不是 `border-bottom`：
  表格是 `border-collapse: collapse`，吸顶的 `th` 在 Chrome 里画不出被折叠掉的那条边框，
  滚动时表头会和内容粘成一片。
- 滚动条收成 8px 细条、颜色走 `var(--line)`，暗色下不会是一道白槽；明细换页后调 `refold()`
  重算，否则新一页行数不同高度就对不上。

`/s/` 落地页只在**真的建了快照**时才记一条，命中 6 小时缓存的重复打开不计数，
否则同一部剧被反复点开会把"查询次数"灌水。

### 几点设计上的取舍

- **登录失败限流**：同一来源 15 分钟内最多错 8 次，之后返回 429 并提示还需等多久；纯内存，重启清零。
- **CSRF**：登录与退出表单都带一次性 token，登录后立刻换一枚。
- **会话**：`HttpOnly + SameSite=Lax` cookie，8 小时有效。
- **IP 只能采信一次**：只有当直接连过来的那一跳是回环地址（也就是本机 nginx）时才读
  `X-Forwarded-For` 的最左一项，规则与 `TrustForwarded` 完全一致。外部直连时这个头是自己写的，
  采信就等于让访问者随便伪造统计里的来源。写入前还会用 `ipaddress` 解析一次，解析不出的一律丢弃，
  所以这个字段里不会混进换行或任意文本。
- **默认全是 127.0.0.1**：只监听回环时所有记录 IP 都是 127.0.0.1，按 IP 分组没意义；
  要按设备区分得 `--host 0.0.0.0` 或挂反代。
- **统计写不进去也不影响搜索**：`record()` 整个包在 try 里，磁盘满、库被别的过程锁住，
  搜索照常返回。
- **保留期**：默认只留 365 天，更早的记录在初始化时清掉（每小时最多清一次），
  环境变量 `ZHUIJU_STATS_KEEP_DAYS` 可改。
- **不进搜索引擎**：`/robots.txt` 里 `Disallow: /admin`，页面本身也带 `noindex`。
- **统计写入失败不影响搜索**：`record()` 整个包在 try 里。但这也意味着"库结构升级失败"
  会表现为"归属地一直是空的"而没有任何提示，所以 `ensure_schema()` 的出错原因记在
  `stats.MIGRATE_ERROR` 里，统计页顶部会直接显示出来。
- **归属地不联网**：解析全在本地 xdb 里完成，不会把访客 IP 发给任何第三方接口或地图瓦片服务。
- **公网暴露前请先想清楚**：这个口令是给"同事乱点"设的门槛，不是严格的多人账号体系。
  要放到能被公网访问的地址，至少得配合 HTTPS，并考虑在 nginx 上再加一层基本认证。

验收：`.venv\Scripts\python.exe tests\test_admin_stats.py`（离线，不联网）。统计库和口令文件
都被指到临时目录，不会碰你正在用的那份数据；覆盖口令生成与修改、环境变量覆盖、
写入/过滤/分页/聚合、脏输入与注入串、XFF 采信规则、限流、未登录不泄漏数据、
登录全流程、三个入口的埋点、以及"统计库打不开时搜索仍 200"。

## 部署到 Linux（宝塔面板）

本仓库里所有命令示例都是 Windows 写法。Linux 上把 `.venv\Scripts\python.exe`
换成 `.venv/bin/python`；用宝塔的话把站点根目录 `zhuiju.env` 建好（见下），
`sh refresh.sh --check-env` 会把它最终会用哪个解释器打出来。

**别把 Windows 的 `.venv` 目录传上去。** venv 不可移植：里面是 Windows 的 exe 和指向本机
的 `pyvenv.cfg`。传上去之后 `exec` 会得到

```
OSError: [Errno 8] Exec format error: '/www/wwwroot/zhuiju/.venv/Scripts/python.exe'
```

六个步骤挂在同一行上、`seconds` 只有 0.1 —— 就是这个原因（以前 `tools/refresh.py` 写死了
那个路径）。删掉 `.venv`，在服务器上用宝塔的 Python 环境重建，或者：

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 解释器与端口写在哪

宝塔创建的 venv **在站点目录外面**，例如 `/www/server/pyporject_evn/zhuiju/bin/python`。
代码不再假设它在哪儿：`autoupdate.python_bin()` 按
`ZHUIJU_PYTHON` → 正在跑站点的那个解释器 → `ZHUIJU_VENV` 指的目录 → 站点内 `.venv|venv|env`
的顺序现找，并且真的跑一句 `import flask, requests` 确认依赖齐不齐，缺依赖的候选不会被选。
所以站点自己触发的更新本来就用对了解释器，什么都不用配；要手动跑 `tools/*.py` 才需要指一下：

```sh
# 站点根目录建 zhuiju.env（模板是 zhuiju.env.example；这文件已被 git 忽略，因为可以写口令）
ZHUIJU_PYTHON=/www/server/pyporject_evn/zhuiju/bin/python
ZHUIJU_PORT=5000
```

`zhuiju.env` 在导入 `zhuiju` 包时读取，只认列出的那几个键，值两边的引号和 CRLF 的 `\r` 都会去掉，
**已经设了的环境变量优先**。`ZHUIJU_VENV` 则给"不想写全路径"的场合用（指到 venv 目录即可）。

选出来的路径**故意不做 `resolve()`**：venv 里的 `bin/python` 通常是指向真解释器的软链接，
一解析就跑到 venv 外面了，`site-packages` 跟着丢——探依赖时明明齐全，真跑起来却说 import 不到
flask。`tests/test_deploy_paths.py` 用一条带 `..` 的路径钉住了这个行为。

### 权限与要带过去的文件

`zhuiju/data/` 和 `logs/` 必须能被跑站点的那个用户写（宝塔通常是 `www`）——更新状态、进度、
锁、SQLite 统计库、`data/cache/` 全在那里：

```sh
chown -R www:www /www/wwwroot/zhuiju
```

只用标准库 + Flask + requests，没有别的二进制依赖。开发实测在 Python 3.13；宝塔常见版本
（3.8–3.12）里那些新式类型标注都被 `from __future__ import annotations` 推迟了，不会在运行时求值，
但**低版本我没有真跑过**，装完先跑一句 `sh refresh.sh --check-env` 确认依赖 import 得动。

跟着 git 走的三个数据文件（`sources.json` / `templates.json` / `catalog.json`）克隆下来就有；
`admin.json`、`stats.db`、`refresh_state.json`、`data/geo/` 都被 git 忽略，属于本机数据：
口令会在服务器首次启动时随机生成并打印一次（登录后领你改），统计库要从本机拷才留得住历史，
归属地库要重跑一次 `sh refresh.sh` 之外的那条命令：

```sh
.venv/bin/python tools/fetch_geo.py        # 约 14MB，走 gh-proxy 镜像链
```

多久"，不用登服务器翻日志。更新仍然**只在访问时触发**，不需要 cron 或计划任务；一轮失败后默认

## 端口与反向代理

端口有三种指定方式，优先级从高到低：

```bat
python run.py --port 8000              :: 命令行
python run.py --port 8000 --host 0.0.0.0   :: 同时允许局域网访问
set ZHUIJU_PORT=8000 && python run.py  :: 环境变量
启动.bat 8000                          :: 双击脚本带参数（第二个参数是 host）
```

端口被占用时会直接说明并给出两条出路，而不是抛一句 Flask 的堆栈：

```
端口 8124 已被占用。
  换个端口：  python run.py --port 8000
  或先结束占用进程：  python tools/restart.py --port 8124   （它会先杀干净再起）
```

`tools/restart.py --port N` 用 WinAPI 查出监听该端口的进程并结束，再验证新代码已生效——旧进程占着端口、页面却跑旧代码这个坑踩过两次，所以固化成了工具。

### 用 nginx 挂到域名

支持，代码里已为反向代理做了两件事：

- `TrustForwarded` 中间件读 `X-Forwarded-Proto` / `-Host` / `-Prefix`，让 `canonical`、`og:url`、`sitemap.xml` 生成的是你的域名而不是 `http://127.0.0.1:5000/`。**只信任来自回环地址的转发头**，否则任何人都能用一个伪造的 Host 头污染规范链接。必须是 WSGI 中间件而不是 `before_request`——Werkzeug 在建 `Request` 时就算好了 `host_url`，实测在 `before_request` 里改 `environ` 完全无效。
- `/img` 图片代理只服务**本站页面发出过的地址**（`imgproxy.register`，登记表在 `zhuiju/data/cache/img_urls.json`，上限 3000 条按登记序淘汰）。不这么做的话，挂到域名上它就成了任何人都能驱使的公共图片代理。设 `ZHUIJU_IMG_OPEN=1` 可关掉这层限制，公网暴露时别关。

一份能用的 nginx 配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:5000;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Host  $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP         $remote_addr;
}
```

三个要注意的边界：

1. **必须挂在域名根路径**。页面里的资源都是 `/static`、`/api`、`/s/`、`/img` 这样的绝对路径，挂到子路径（如 `/zhuiju/`）会全部 404。要挂子路径就给 nginx 加 `proxy_set_header X-Forwarded-Prefix /zhuiju;` 并把代码里的路径改成 `url_for`——目前没做这一步。
2. **Werkzeug 自带服务器不适合对外提供服务**（单进程、无连接管理）。挂域名前建议换 waitress：`pip install waitress -i https://pypi.tuna.tsinghua.edu.cn/simple`，然后 `python -c "from waitress import serve; from zhuiju.app import create_app; serve(create_app(), listen='127.0.0.1:5000', threads=8)"`。
3. 一旦公网可访问，"访问时触发自动更新"就意味着访客和爬虫也会触发更新（有当天标记与 5 分钟重启间隔兜底，一天只会真跑一次）；同时页面上那些第三方资源站链接也就公开了，这属于你要不要承担的范围。

## 维护

第三方公开接口随时会失效，失效的源不会静默吞掉结果，页面顶部会标出哪个源挂了（鼠标悬停看原因）。

```bat
:: 日常：体检所有检索源 + 首页可浏览性，只保留能返回片名的
.venv\Scripts\python.exe tools\probe_sources.py 庆余年

:: 目录数据有更新时
.venv\Scripts\python.exe tools\build_catalog.py

:: 想换/加检索源，按这个顺序走一遍
.venv\Scripts\python.exe tools\harvest_apis.py
.venv\Scripts\python.exe tools\test_apis.py
.venv\Scripts\python.exe tools\test_apis_extra.py
.venv\Scripts\python.exe tools\harvest_templates.py
.venv\Scripts\python.exe tools\verify_get_templates.py
.venv\Scripts\python.exe tools\build_templates.py
.venv\Scripts\python.exe tools\probe_sources.py 庆余年
.venv\Scripts\python.exe tests\test_smoke.py
```

脚本产生的中间文件都落在 `.probe/`（可随时删，重跑即可）。浏览器直接访问 `http://127.0.0.1:5000/api/health` 也能看当前源状态。

收录标准只有一条：**本机实测能返回片名才写进配置**，所以 15 个 TVBox 配置里只有 3 个能打开、抽出的 16 个候选接口最后只留 8 个，这是真实数字而不是漏配。

## 限制与说明

- 采集接口是第三方公益站，稳定性、片源完整度都不受控；某个源挂了直接影响结果数，页面顶部会标出是哪个源，可多试几种关键词写法（只留主标题、去掉"第 X 季"）。
- `tools/probe_sources.py` 只验证"能返回片名"，不验证点开能不能真播。
- **网盘这一类拿不到结果，而且是原理性的限制**：目录里 4 家网盘站（PanSou、夸克搜、追剧吧、谷哥搜）的搜索框是 POST 表单或纯 JS 提交，GET 拼关键词不生效，实测每种变体返回的都是和首页一样的 JS 空壳。考虑过自建 [pansou](https://github.com/fish2018/pansou) 补这块，但它的数据源是 **Telegram 公开频道**——本机网络访问不了 Telegram，所以这条路走不通，已放弃（相关代码也已删除，不留半成品）。
- 「网盘查询」标签页因此只对**搜索页直接返回 HTML** 的站做服务端抓取与解析（庆余年实测 20 站中 2–3 站出结果、约 14–16 条），其余站逐条标注原因并给"打开该站搜索页"入口；只收与搜索页同域的链接，跨域的基本是广告。
- 76 个直达站点里 18 个有已验证的站内搜索路径，其余 58 个退回首页，页面上逐条标注了。
- 8 个检索源里 4 个（虎牙 / 火狐 / 极速 / 光速 / 备番）首页返回 403 或 500，属于只开放 API 的采集站，这类结果不显示"打开站点"，以免跳到拦截页。
- 结果标题带"同系列版本 / 近似名称 / 模糊匹配"标记的，是接口返回的续作、特别版或同名蹭名作品（例如各种"庆余年之××"短剧）；完全同名的正片排在最前。
- 英文片名往往搜不到，这些接口收的是中文片名，请换中文译名（如 Oppenheimer → 奥本海默），无结果时页面也会提示。
- 本工具只做第三方公开接口的聚合查询，不存储、不转发任何影视内容；外链安全性由使用者自行判断。仅供个人技术学习与找片参考，请支持正版。
- **会存查询日志**：`zhuiju/data/stats.db` 里记着"哪个 IP、用什么浏览器和系统、从哪个页面来、
  在什么时候搜了什么词"，另有
  `zhuiju/data/queries.jsonl`（给 sitemap 用）与 `logs/`。这三个文件都只在你的机器上、
  且都进了 `.gitignore`；不想留就把 `stats.db` 删掉，它会自动重建。想彻底不记，
  把 `zhuiju/app.py` 里的 `_record()` 调用注掉即可（统计页会因此变空）。
- 后台统计页 `/admin` 只有一层口令，够挡住乱点的同事，不够当多人账号体系用；
  要挂到能被公网访问的地址，先配合 HTTPS，并考虑在 nginx 上再加一层基本认证（见"后台统计"一节）。
